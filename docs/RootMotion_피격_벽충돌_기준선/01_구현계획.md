# 01. 현재 구현과 기준선 개발 계획

기준일: 2026-11-02 KST. **공격·피격 기능은 구현되어 있고, 반복 가능한 정량 기준선은 아직 개발해야 한다.** 아래에서 “기존”과 “신규 제안”을 구분한다. 현재 실행법은 [04](04_공격피격_실행.md), 연구 개선은 [06](06_후속개선_상세설계.md)을 따른다.

## 1. 현재 실행 경로와 코드 근거

```text
MeleeAttackComponent.RequestAttack
  → ServerRequestAttack (서버 승인/Combo Input Notify 구간에서만 다음 1입력)
  → StartAttack / MulticastAttack(Index, AttackId)
  → 공격 Montage의 AttackHitWindow Notify
  → BeginHitWindow / CheckHitWindow
  → overlap + Box sweep + Visibility 차폐 검사
  → ICombatHitReceiver.ReceiveCombatHit (Actor 또는 Component)
  → HitReactionComponent.MulticastState(ReactionId/활성/Montage/서버 시각)
  → Montage_Play → 기본 CMC Root Motion/벽 충돌 → ReactionEnded
```

Player는 IgnoreRootMotion으로 제자리 공격, Enemy는 RootMotionFromMontagesOnly로 피격 이동한다. 서버의 pose/bone tick을 유지한다. 피격 이동에 Impulse·Launch·래그돌을 더하지 않는다. 공격 multicast와 피격 multicast는 각 ID로 중복 재생을 막는다.

별도 Character와 레벨, R/HitWallReset은 제거했다. 기존 SharpReset과 실험 제어를 사용하며 피격 일시 정지는 Generation/Segment를 유지한다. 피격 상태에 서버 시작 시각을 포함하지만 연구용 TrialId·에셋 revision·phase 계획 공유와 전용 정량 피격 Trial은 후속 작업이다. 상세 통합 규칙은 [04](04_공격피격_실행.md)를 따른다.

## 3. 기준선에서 고정할 계약

| 항목 | 기준선 정책 |
|---|---|
| 피격자/역할 | 서버 Enemy 1개. Client에서는 Simulated Proxy |
| 공격 | 기존 3종 기능을 보존하고 측정에서는 Attack 01만 1회 사용. 고정 실행 진입점 추가 필요 |
| 피격 | 고정 Montage·Section·play rate·blend. 현재 0.75초 후보의 L/T를 먼저 검증 |
| 충돌/복제 | 기본 CMC·Capsule·Root Motion 복제·smoothing 유지 |
| 환경 | 평지와 정적 수직 벽. 초기 overlap 제외 |
| 상태 식별 | RunId / TrialId / ActorId / Generation / ReactionId / Role |
| 측정창 | 공격 전 0.5초 이상 → 피격 → 서버 종료 → 최소 1초 tail. pilot에서 길이 동결 |
| 리셋 | 저장 완료 뒤 준비 단계에서만 teleport. 리셋 변위를 지표에서 제외 |

기능 시연의 01→02→03 순환을 그대로 반복하면 공격 종류와 명중 시점이 조건 간 섞인다. Manager가 고정 1타를 요청하는 실험 경로를 추가하고, 기존 순환/입력 예약과 실행 종류를 manifest로 구분한다. 적 피격 중 재명중 거부도 사건으로 남긴다.

## 5. Trial 수명과 네트워크 보완

```text
Preparing → Ready → Attacking → Reacting → ObservingTail → Saving → Completed
                         ↘ Missed / Interrupted / Failed
```

1. 준비 시 참가자·에셋·역할·바닥·초기 겹침을 확인한다. Montage/이동/이전 타이머를 정리하고 시작 Transform을 서버에서 배치한다.
2. 복제 안정화와 참가자 Ready 후 TrialId를 확정하고 기록을 먼저 시작한다.
3. 고정 Attack 01을 한 번 요청한다. 명중·미명중·거부를 각각 기록한다. 이동 실패를 단순 재시도로 숨기지 않는다.
4. 서버 명중 시 ReactionId를 확정한다. 고정 참가자 기준선은 현재 reliable multicast 경로를 유지하면서 Trial 문맥과 서버 시각·고정 asset 식별을 보완할 수 있다.
5. 서버도 multicast 경로에서 한 번만 재생한다. RepNotify를 보조로 추가해도 두 번째 재생 시작점이 되지 않게 같은 ID로 처리한다. 수신 지연만큼 무조건 seek해 Root Motion 이동을 건너뛰지 않는다.
6. 서버 Montage 종료/중단과 클라이언트 종료 시각을 따로 기록한다. tail·flush·저장 확인 후에만 다음 Trial 준비를 허용한다.
7. 늦은 이전 문맥의 시작/종료/콜백은 무시하고 그 사유를 남긴다. watchdog은 정상 동작을 자르지 않게 Montage 길이·재생 속도·네트워크 여유로 설정한다.

기준선에서는 벽 접촉을 관찰만 한다. 접촉으로 피격을 조기 종료하거나 목표를 축소하는 기능은 후속 비교군에 넣는다. Enemy 결과를 owner correction 결과로 해석하지 않는다.
