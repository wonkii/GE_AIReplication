# 05. 참고논문과 개발 항목의 연결

확인일: 2026-11-02 KST. 아래는 기존 연구계획의 핵심 3편을 원문과 공식 자료로 재확인한 결과다. 포괄적인 최신 문헌 조사나 신규성 검증을 완료했다는 뜻은 아니다. **논문에서 확인한 내용**과 **이 프로젝트에서 새로 설계하는 내용**을 구분한다.

## 1. 논문 A — Environment-aware Motion Matching

**Jose Luis Ponton, Sheldon Andrews, Carlos Andujar, Nuria Pelechano. 2025.** ACM Transactions on Graphics 44(6), Article 232, SIGGRAPH Asia 2025. DOI: [10.1145/3763334](https://doi.org/10.1145/3763334). [원문 arXiv v1](https://arxiv.org/html/2510.22632v1), [공식 코드](https://github.com/UPC-ViRVIG/Environment-aware-Motion-Matching).

**원문에서 확인한 원리:** 자세·궤적·신체 형태의 특징을 사전 추출하고, 실행 시 주변 장애물 비용을 검색 점수에 포함해 동작을 고른다. 원문의 §4.1은 특징 표현, §4.2는 장애물 페널티를 포함한 검색, §5는 실행 구조, §6은 평가와 효과 분리를 설명한다. [근거: 원문 §4–6](https://arxiv.org/html/2510.22632v1).

**우리의 적용안:** BackLong/BackShort/InPlace/WallHit 후보를 준비하고, 실제 Capsule 경로의 충돌 위험·동작 연결·요청 밀림 보존을 평가해 서버가 하나를 고른다. 대규모 포즈 검색보다 작은 Montage 라이브러리부터 시작한다. 구현은 [06의 후보 라이브러리·위험 평가](06_후속개선_상세설계.md)에 정의한다.

**차이와 제한:** 우리의 후보 비용식, Capsule sweep, 네트워크 행동 계획은 프로젝트 설계다. 논문의 신체 표현·검색식·컨트롤러를 동일하게 구현하는 것이 아니므로 “EMM 재현”으로 부르지 않는다. 공식 저장소는 Unity 코드와 MIT 라이선스를 제공하지만 애니메이션 데이터·의존성의 사용 조건은 별도 확인한다. [근거: 공식 저장소](https://github.com/UPC-ViRVIG/Environment-aware-Motion-Matching).

## 2. 논문 B — A Physics-Aware Dead Reckoning Technique for Entity State Updates in Distributed Interactive Applications

**Patrick J. Walsh, Tomás E. Ward, Séamus C. McLoone. 2012.** IET Irish Signals and Systems Conference, NUI Maynooth, 2012-06-28~29. [기관 서지](https://mural.maynoothuniversity.ie/id/eprint/4164/), [원문 PDF](https://mural.maynoothuniversity.ie/id/eprint/4164/1/SMcL_ISSC2012_physics.pdf).

**원문에서 확인한 원리:** 물리 접촉은 작은 위치 불일치를 다른 객체로 전파할 수 있다. §II는 physics-consistency-cost, §III는 동적 권한·접촉 종료 갱신·연쇄 접촉·적응형 DR 임계값을 다룬다. 접촉 시작의 단일 갱신만으로 충분하지 않은 경우와 접촉 해제 때 상태를 다시 전달하는 필요성을 설명한다. [근거: 원문 §II–III](https://mural.maynoothuniversity.ie/id/eprint/4164/1/SMcL_ISSC2012_physics.pdf).

**우리의 적용안:** 먼저 ContactEnter/Stay/Exit를 구분해 기록한다. 주 비교가 끝난 뒤, 같은 행동 계획에서 접촉 진입/해제 갱신과 짧은 Burst의 추가 효과를 따로 실험한다. 정적 벽은 갱신할 동적 상태가 없으므로 초기 대상은 피격 캐릭터다.

**차이와 제한:** P2P의 동적 권한 이전을 도입하지 않는다. 서버 권한·CMC 충돌을 유지한다. “벽에서 update를 늘리면 반드시 개선된다”는 결론은 우리 실험으로 확인해야 한다. 다른 Enemy/동적 장애물의 연쇄 접촉은 후속 확장이다.

## 3. 논문 C — Predictive Dead Reckoning for Online Peer-to-Peer Games

**Tristan Walker, Barry Gilhuly, Armin Sadeghi, Matt Delbosc, Stephen L. Smith.** IEEE Transactions on Games 16(1), 173–184, **2024 권호**. DOI: [10.1109/TG.2023.3237943](https://doi.org/10.1109/TG.2023.3237943). [저자 공개 PDF](https://ece.uwaterloo.ca/~sl2smith/papers/2023TOG-Predictive_Dead_Reckoning.pdf), [저자 서지](https://ece.uwaterloo.ca/~sl2smith/publications.html), [공식 코드](https://github.com/ubisoft/ubisoft-laforge-predictive-dead-reckoning). 온라인 공개 연도 2023과 권호 연도 2024를 구분한다.

**원문에서 확인한 원리:** 차량 복제를 미래 상태 예측·부드러운 경로 추종·정적 장애물 충돌 대응으로 나누고 신경망과 제어기를 결합한다. §II는 문제와 정적 환경 가정, §III는 구조, §IV는 평가다. 동적 플레이어 간 충돌을 검증 범위에 포함하지 않는다. [근거: 원문 §II–IV](https://ece.uwaterloo.ca/~sl2smith/papers/2023TOG-Predictive_Dead_Reckoning.pdf).

**우리의 적용안:** 피격 요청 궤적, 실제 충돌 후 Capsule 이동, 클라이언트 표시 복구를 별도로 기록하고 평가한다. Playing/WallContact/Recovering 구간을 구분해 평균 위치 오차에 충돌 문제가 묻히지 않도록 한다.

**차이와 제한:** 차량용 FC/LSTM·충돌 신경망을 신규 학습하거나 CMC 대신 적용하지 않는다. Root Motion과 CMC를 실행 기반으로 사용한다. 논문의 개선 수치를 UE 피격의 기대 성능으로 옮기지 않는다.

## 4. 엔진 구현 근거 — 논문과 별도로 읽을 공식 문서

| 공식 자료 | 확인할 내용 | 개발 시점 |
|---|---|---|
| [Root Motion](https://dev.epicgames.com/documentation/en-us/unreal-engine/root-motion-in-unreal-engine) | 루트 이동 추출과 Character 이동 설정 | 기준선 에셋 검증 |
| [Animation Montage](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-montage-in-unreal-engine) | Montage 재생과 네트워크 사용 주의사항 | 재생 경로/중복 처리 |
| [CMC Networked Movement](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-networked-movement-in-the-character-movement-component-for-unreal-engine) | Authority/Autonomous/Simulated 이동, saved move, correction, Root Motion | 역할별 계측·owner replay |
| [FRepRootMotionMontage](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/FRepRootMotionMontage) | 엔진이 전달하는 Root Motion 상태 계약 | 관찰 가능한 상태 확인 |
| [Motion Warping](https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-warping-in-unreal-engine) | 플러그인·Warp Window·이름 있는 target을 통한 Root Motion 정렬 | 안전 실행 |

Motion Warping은 목표에 루트 이동을 맞추는 수단이다. 안전 목표 계산·전체 경로 충돌 검사·권한과 계획 전달은 별도로 개발한다. [근거: Motion Warping 공식 문서](https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-warping-in-unreal-engine).

엔진 계측 API의 가상 함수 여부·접근성·호출 순서는 **설치된 UE 5.8 소스**로 최종 확인한다. 기존 계획의 훅 이름을 곧바로 구현 가능하다고 간주하지 않는다. correction 경로·Root Motion fixup·Mesh smoothing을 동일한 이벤트로 집계하지 않는다. [관련 기반: CMC 공식 설명](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-networked-movement-in-the-character-movement-component-for-unreal-engine).

## 5. 논문에서 개발·검증으로 이어지는 추적표

아래 개발 이름과 실험은 **이번 프로젝트의 제안**이다.

| 출발점 | 개발 산출물 | 확인할 가설/관찰 | 비교 방법 |
|---|---|---|---|
| A의 환경을 포함한 동작 선택 | 후보 Library/Baker, RiskEvaluator, Score/Planner | H1: 공간별 후보 선택의 추가 효과 | E-S vs F-S |
| B의 접촉과 불일치 비용 | Contact 기록·전환, 후속 ContactUpdatePolicy | 접촉 전후 오차/추가 전송 효과 | 동일 계획의 전송 정책만 변경 |
| C의 예측·충돌·표시 분리 | Root Motion/CMC/표시 Recorder, 구간별 분석 | 어느 단계에서 오차가 생기는가 | W0 vs W2/W3, 역할별 비교 |
| CMC 기반 + 이번 동기화 설계 | ReactionPlan·revision/history·owner replay | H2: 공유 실행 계획의 추가 효과 | F-S vs F-L, E-S vs E-L |
| 이번 비용 통제 설계 | Connection Recorder·calibration·품질/비용 곡선 | H3: 같은 비용에서도 효과가 남는가 | 실제 bytes/s 구간의 군별 비교 |

군 이름과 평가법은 [07](07_단계별작업과평가.md)에 정의한다. 후보 선택 효과와 계획 공유 효과를 나누고, Burst는 주 비교 뒤에 추가한다. 신경망 학습과 전체 Motion Matching 도입은 첫 개발 범위에 포함하지 않는다.

## 6. 읽기와 구현 준비 순서

1. 01/04로 현재 실행과 미구현 범위를 확인한다.
2. Epic Root Motion/CMC 문서로 정상 엔진 기준선을 먼저 고정한다.
3. 논문 A §4–6을 읽고 작은 후보 선택기로 옮길 특징·평가 항목을 결정한다.
4. 논문 C §II–IV를 읽고 이동/충돌/표시 구간의 계측 경계를 점검한다.
5. 논문 B §II–III를 읽고 접촉 수명과 후속 전송 실험을 설계한다.
6. 06의 API/데이터 계약을 설치 엔진과 대조하고, 07의 완료 관문에 따라 개발한다.

연구 기여 후보는 **환경별 피격 선택 + CMC 안의 안전 실행 + 서버 계획 공유를 통합하고 효과·비용·행동 품질을 분리 검증하는 것**이다. 최초 제안이라는 주장은 별도 문헌 조사 후 판단한다.
