# 04. Lv_Jang 공격·피격 실행과 확장

2026-11-02 KST. 기존 `/Game/JWJ/Lv_Jang`의 Player와 Sharp Enemy에서 실행한다. 별도 HitWall Character, BP, Controller, GameMode, 테스트 레벨과 이전 생성/검사 스크립트는 삭제했다. 공통 코드는 `Source/GE_AIReplication/Combat`, 에셋은 `/Game/Combat`에 있다.

## 실행

1. Editor Development를 빌드하고 `Lv_Jang`을 연다. PIE에서는 기존 Player, 독립 실행에서는 기존 LAN 메뉴의 명시적 접속 절차를 사용한다.
2. 기존 Enemy에게 접근해 좌클릭한다. 새 공격은 01에서 시작한다. 각 Montage의 `Combo Input Window`에서만 다음 1타를 입력할 수 있다. 구간이 자연 종료될 때 입력이 있으면 해당 Notify의 Next Attack Index로 연결하고, 없으면 현재 공격을 마친다. 구간 밖 입력은 저장하지 않는다. 이동·점프는 공격 동안 잠긴다.
3. Notify 구간의 손/발 Socket Box가 Enemy Capsule에 닿으면 서버가 차폐·접지 상태를 검사한다. 같은 공격은 같은 대상을 한 번만 처리한다. 피격 중 재명중은 거부하며, 측면·후방도 Socket 판정에 닿으면 허용한다.
4. Enemy가 Root Motion 피격 Montage를 실행한다. Spline 이동 중이었다면 종료 후 현재 위치에서 경로를 다시 투영해 재개한다. Ready/Stopped/Completed Enemy는 원래 상태를 유지한다.
5. 기존 `SharpPrepare`, `SharpStart`, `SharpStop`, `SharpReset`과 Manager 제어를 사용한다. 이전 R/HitWallReset은 제거했다. Reset 시작 Capsule이 Player 등에 막히면 기존 배치 검증이 Reset을 거부하므로 공간을 비운다.

첫 피격으로 Enemy가 사거리 밖으로 이동하면 예약된 후속 공격은 빗나갈 수 있다. 기존 세 Enemy 배치와 Path/Impulse 연결, GameMode·PlayerController·LAN 흐름은 유지한다.

## 책임과 확장

| 구성 | 책임 |
|---|---|
| `UMeleeAttackComponent` | 입력/서버 RPC, Notify 구간 안의 다음 1타 입력, Socket overlap/sweep·차폐·대상별 중복 방지. 전체 공격 중 누적하던 예약 카운터 제거 |
| `ICombatHitReceiver` / `FCombatHit` | Actor 또는 ActorComponent가 구현하는 공통 피격 계약. Actor 구현을 우선하고 없으면 구현 컴포넌트 하나를 찾는다. 공격자는 Enemy 클래스에 의존하지 않는다. |
| `UHitReactionComponent` | 공통 피격 계약, 접지·중복 상태 검사, ReactionId, multicast + RepNotify 상태, Montage/Root Motion·회전 설정 저장/복원, 중단·watchdog |
| `UAnimNotifyState_AttackHitWindow` | Montage의 Notify 구간 동안만 공격 Box를 QueryOnly로 활성화. 종료/중단 시 NoCollision |
| `UAnimNotifyState_ComboInputWindow` | Montage에서 입력 허용 구간과 다음 공격 인덱스 지정. 자연 종료 시 다음 공격 연결, 중단 시 입력 폐기 |
| `USharpCombatAdapterComponent` | Reaction 이벤트를 Sharp 실험 일시 정지·재개와 Predictor 표시 제어에 연결. 공통 전투 코드는 Sharp에 의존하지 않는다. |
| `UCombatAssetSetup` | 원본을 보존하는 공통 AnimBP/Montage/Root Motion Sequence 생성. 기존 공통 애니메이션은 덮어쓰지 않는다. |

다른 복제 Character에서 공격을 사용하려면 `UMeleeAttackComponent`와 에셋을 추가하고 `BindInput` 또는 Blueprint `RequestAttack`을 연결한다. 이동·점프 제한은 해당 Character 입력 경로에 연결한다. 피격은 `UHitReactionComponent`의 `HitMontage`와 `Combat Enabled`를 설정한다. 별도 피격 규칙은 Actor/Component에서 `ICombatHitReceiver`를 구현한다. AI 중단 정책은 `OnReactionChanged`에 어댑터로 연결한다. 현재 Character 클래스에는 컴포넌트 생성과 입력·이동 제한 연결만 둔다.

## Sharp 기능과 충돌 처리

- 피격 동안 Spline 입력과 자동 회전을 멈추고 기본 CMC로 Root Motion/충돌을 실행한다. Launch·Impulse·직접 위치 보간을 피격 이동에 더하지 않는다.
- 일시 정지는 Generation/Segment를 유지한다. `ResumeInput → Start`를 호출해 새 기록 구간을 만들지 않는다.
- 기존 Impulse 타이머와 피격 잠금을 함께 관리한다. 타이머가 먼저 끝나도 피격 중에는 재개하지 않는다. 피격 중 진입한 Impulse는 적용하지 않고 종료 뒤 소급 적용하지 않는다.
- Stop/Complete/Fail/Release/Reset은 자동 재개 권한을 해제한 뒤 피격을 취소한다. 오래된 Montage 종료 콜백이 새 실험을 재개하지 못한다. 행정적 Suspend가 자동 재개보다 우선한다.
- 클라이언트 피격 동안 Predictor 표시 제어권을 해제하고 기본 CMC smoothing을 복원한다. 피격 이전/도중의 오래된 Snapshot을 종료 후 재사용하지 않는다. Detector/Recorder 관찰은 유지한다.

## 애니메이션

`ABP_PlayerCombat`은 기존 Unarmed AnimBP, `ABP_SharpCombat`은 기존 Enemy의 `ABP_Manny_Combat`을 복제한다. 이동 그래프와 기존 Slot을 보존하고 최종 출력 앞에 `CombatFullBody` Slot을 추가한다. 기존 Player Quinn Mesh와 Enemy Manny Mesh를 유지한다.

| 공격 | Socket / Bone | 타격 구간 | 다음 입력 구간 | Next Attack Index |
|---|---|---|---|---|
| `AM_PlayerAttack_01` | AttackSocket_R / hand_r | 0.300~0.500초 (9~15f) | 0.550~0.867초 | 1 → Attack 02 |
| `AM_PlayerAttack_02` | AttackSocket_L / hand_l | 0.367~0.567초 (11~17f) | 0.600~0.867초 | 2 → Attack 03 |
| `AM_PlayerAttack_03` | AttackSocket_FootR / foot_r | 0.400~0.600초 (12~18f) | 0.917~1.533초 | 0 → Attack 01 |

시간은 현재 저장된 Montage 기준이며 프레임 표기는 30fps 기준이다. `/Game/Combat/Animations/AM_PlayerAttack_01~03`을 열고 Notifies 트랙의 **Attack Hit Window**와 **Combo Input Window** 양끝을 움직여 각각 조정한다. Hit Notify에서는 Socket/Box Extent/Offset, Combo Notify에서는 **Next Attack Index**(컴포넌트 AttackMontages 배열의 0부터 시작하는 인덱스)를 편집한다. 입력 구간 끝은 Blend Out 시작 전으로 둔다. 같은 종류 구간을 겹쳐 배치하지 않는다.

전환 시각과 다음 공격은 런타임 타이머나 이전 Animation/SavedMove 재생으로 결정하지 않는다. 현재 재생 Montage의 Notify가 정하고 컴포넌트는 현재 공격 인스턴스와 다음 입력 1개의 유무만 관리한다. Notify 종료가 중단에 의한 것인지 자연 종료인지 구분한다. 오래된 Montage/인스턴스의 Notify는 새 공격의 Collision·입력 상태를 닫거나 다음 공격을 시작할 수 없다. 서버가 입력 구간과 AttackId를 다시 검증하고 전환을 복제한다.

공격 컴포넌트는 Root Motion Mode를 덮어쓰지 않는다. 공격 AnimBP의 Class Defaults에서 Root Motion from Montages Only를 사용하고 Montage가 실제 참조하는 Sequence의 Enable Root Motion과 루트 변위를 확인한다. 피격 컴포넌트는 피격 중 RootMotionFromMontagesOnly를 적용하고 종료 시 이전 설정을 복원한다. `AM_HitReaction_Front`는 Root Motion을 켠 복제 Sequence `AS_HitReaction_Front`를 사용한다. 길이는 0.75초다. 서버의 pose/bone tick을 유지한다. 연구용 긴 피격 후보와 L/T 확정은 별도 작업이다.

### 공격 Root Motion 진단에서 확인한 생성기 오류

`UAnimMontage` 생성자는 빈 DefaultSlot 트랙을 만든다. 그 상태에서 CombatFullBody 트랙을 Add하면 0번은 빈 트랙, 1번은 실제 공격 트랙이 된다. UE 5.8의 Montage Root Motion 추출은 첫 트랙을 사용하므로 HasRootMotion=true여도 이동 추출량은 0이 된다. 생성기는 트랙을 초기화한 후 실제 트랙 하나를 만들도록 수정했다. 기존 공통 공격 Montage는 맨 앞의 빈 DefaultSlot만 제거해 Notify 시간·Socket·다음 공격 인덱스를 유지했다. EnsureAttackNotifyWindows는 이 이전 생성 오류도 복구한다.

수정 전 Montage 추출량은 세 개 모두 0cm였다. 수정 후 Sequence와 Montage의 추출량은 각각 150.612cm, 90cm, 216cm로 일치한다. 기능 검사에는 이제 공격자 Capsule 이동 확인도 포함한다. Source/Raw/Compressed 본 포즈가 맞는 것과 Montage에서 Root Motion을 추출하는 것은 별도로 확인해야 한다.

피격은 ID·활성 여부·Montage·서버 시작 시각을 함께 복제한다. 중복은 다시 재생하지 않고 만료된 상태는 늦게 수신해도 재생하지 않는다. Montage 시각 정렬과 기본 CMC 위치/Root Motion 복구를 사용하며 과거 변위를 Capsule에 직접 더하지 않는다. late join·심한 지연·owner replay의 정량 품질 검증은 후속 작업이다.

## 설정과 검사

에디터를 닫고 `UnrealEditor-Cmd <project> -run=pythonscript -script=<Scripts/ConfigureJangCombat.py 절대 경로> -SCCProvider=None -unattended -nullrhi -nosound`를 실행한다. `-SCCProvider=None`은 에디터의 자동 Git stage를 방지한다. 구성기는 작업별 README/manifest를 생성하고 기존 Player/Enemy BP를 연결한다. `Lv_Jang` 맵을 재생성하거나 저장하지 않는다. 삭제 대상 `/Game/RootMotionHitWall` 패키지는 외부 참조 검사 후 정확한 하위 경로에서만 제거한다.

구성기 재실행은 지정한 BP 설정을 다시 적용하므로 의도적인 입력/에셋 변경은 구성기에도 반영한다. 공통 애니메이션의 기존 수동 편집은 보존한다.

BP/레벨을 건드리지 않고 기존 공격 Montage에 누락된 Notify만 추가하려면 같은 commandlet 방식으로 `Scripts/ConfigureAttackNotifies.py`를 실행한다. 이미 있는 Notify의 타이밍·설정은 보존한다. 최초 생성 기본값을 바꾸려면 CombatAssetSetup의 생성 설정을 수정하며, 실행 중 타이밍의 기준은 저장된 Montage다.

`./Scripts/TestJangCombat.ps1`은 실제 Lv_Jang에서 Notify 입력 구간의 3타 연결, 구간 전/후 입력 거부, 구간당 1입력, Collision 활성/해제, 입력을 받은 공격의 중단·예약 폐기, Socket 명중/Root Motion, 중복·벽 차폐 및 후방 명중, Spline 재개/기록 문맥, Impulse 타이머, Stop/Reset/Montage 중단, 기존 3 Enemy Trial 완료와 Dedicated Server/Client RPC·피격 표시를 검사한다. 임시 배치와 테스트 벽은 실행 월드에만 존재한다. README/로그/summary.json은 `Saved/Tasks/*-jang-combat-smoke-*/`에 기록한다. 기능 검증과 연구용 정량 기준선 완료를 구분한다.

## 방향별 피격과 멀티플레이

피격 방향은 서버가 피격 직전 Enemy의 수평 전방/우측 축과 공격자 위치를 비교해 Front / Back / Left / Right의 90도 구역으로 결정한다. 대각선 경계에서는 전후 구역을 우선한다. 공격자와 수평 위치가 같으면 ImpactPoint, 그것도 유효한 방향을 만들지 못하면 기존 전방을 사용한다. 현재 근접 공격은 공격자의 위치를 공격 출처로 사용한다.

서버가 확정한 Direction, FacingYaw, Montage, ServerStartTime은 하나의 FCombatReactionState로 복제한다. 현재 관련성이 있는 클라이언트는 Reliable Multicast로 반응을 시작하고, 도중 접속/관련성 복구는 RepNotify와 서버 시작 시각으로 남은 구간을 재생한다. 종료된 몽타주는 재생하지 않는다. 클라이언트에서 공격자 위치를 다시 계산하지 않는다.

각 피어는 피격 시작 시 자동 회전을 끄고 표시 예측기를 해제한 뒤 서버 FacingYaw를 한 번 적용한다. 실제 공격자 방향을 바라보므로 대각선 공격도 정확한 수평 방향으로 후퇴한다. 위치 이동과 이후 보정은 기존 CharacterMovement의 Montage Root Motion 복제를 사용한다. 종료 시 회전 정책을 복원하고 기존 Spline 재개 흐름을 따른다.

기본값은 기존 HitMontage를 네 방향에서 공유하므로 BP/에셋 재생성이 필요 없다. DirectionalHitMontages에 방향별 변형을 지정할 수 있으며 미지정 항목은 HitMontage로 대체한다. 변형도 공격자를 바라본 상태에서 로컬 뒤쪽(-X)으로 이동해야 한다. 기존 Back 피격처럼 앞으로 이동하는 애니메이션은 그대로 지정하면 요구 동작과 달라진다.

TestJangCombat.ps1은 전용 서버 + 공격 Client + 관찰 Client를 실행한다. 회전된 Enemy의 네 방향 판정, 공격자 바라보기, 실제 Root Motion 후퇴와 두 Client의 방향 수신 및 Capsule 회전/후퇴를 검사한다. 네트워크 지연/손실, late join의 정량 품질은 이 기본 통합 검사 범위에 포함되지 않는다.
