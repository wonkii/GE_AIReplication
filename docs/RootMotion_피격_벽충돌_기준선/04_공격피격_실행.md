# 04. 공격·피격 첫 구현 실행

2026-11-02 KST. 현재 구현은 3종 공격 Montage와 Socket 부착 Box를 Notify로 제어한다. 반복 Trial·정량 Recorder·지연 프로필 실험은 아직 구현 범위가 아니다.

현재 계획의 상태 구분은 [01](01_구현계획.md), 논문 적용은 [05](05_참고논문과개발연결.md), 후속 개발 순서는 [07](07_단계별작업과평가.md)을 따른다. 아래 3종 순환은 기능 시연 경로다. 정량 기준선에는 Attack 01만 1회 실행하는 별도 진입점을 추가할 계획이다.

## 실행

1. `GE_AIReplicationEditor Win64 Development` 빌드 후 프로젝트를 연다.
2. `/Game/RootMotionHitWall/Maps/L_HitWallBaseline`을 연다. 이 맵의 GameMode Override가 전용 Player·Controller를 지정한다. 기존 기본 맵·LAN GameMode는 변경하지 않는다.
3. Play 후 좌클릭한다. 누른 횟수에 따라 01 → 02 → 03 → 01 순환한다. 공격 도중 입력은 최대 두 번 예약된다. 시간 경과에 따른 콤보 초기화는 없다.
4. WASD 이동·마우스 시점 조작은 기존 입력을 사용한다. 공격 중 이동·점프는 잠긴다.
5. R은 공격 종료 후 Player와 Enemy의 시작 위치를 복구한다. 피격 중 Enemy는 리셋하지 않는다. 공격 순번은 유지한다. 콘솔 `HitWallReset`도 같다.

빠른 3회 입력 시 세 공격은 모두 재생되지만, 첫 피격으로 Enemy가 사거리 밖으로 이동하면 후속 공격은 빗나간다. 피격 중 재명중은 Montage를 재시작하지 않는다. 각 타격을 별도로 확인하려면 피격 종료 후 R로 위치를 복구한다.

## 애셋 구성과 조정

원본 공격 Sequence와 지정 피격 Montage는 그대로 참조 기준으로 보존한다. 실험용 애셋은 `/Game/RootMotionHitWall`에 있다.

| 공격 Montage | 원본 | Socket / Bone | 타격 구간 (30fps 기준) |
|---|---|---|---|
| AM_PlayerAttack_01 | MM_Attack_01 | AttackSocket_R / hand_r | 9~15 프레임, 0.300~0.500초 |
| AM_PlayerAttack_02 | MM_Attack_02 | AttackSocket_L / hand_l | 11~17 프레임, 0.367~0.567초 |
| AM_PlayerAttack_03 | MM_Attack_03 | AttackSocket_FootR / foot_r | 12~18 프레임, 0.400~0.600초 |

타격 부위의 전방 뻗기 포즈를 샘플링해 초기 구간을 정했다. 각 Montage의 `Attack Hit Window` Notify State에서 Socket·Box Extent·Offset을 조정할 수 있다. Box half extent는 28cm다. 구간 밖은 NoCollision, 구간 안은 QueryOnly이며 이미 겹친 대상과 프레임 사이 Box 이동 경로를 함께 검사한다. 공격당 같은 Enemy는 한 번만 처리한다. Visibility를 막는 벽 너머 타격과 Enemy 후방 타격은 제외한다.

공유 Skeleton `/Game/Characters/Mannequins/Meshes/SK_Mannequin`에 위 Socket 세 개를 추가했다. `ABP_HitWall`은 기존 Unarmed AnimBP를 복제하고 최종 출력 전에 단일 DefaultSlot을 연결한다. Player는 IgnoreRootMotion으로 제자리 공격, Enemy는 RootMotionFromMontagesOnly로 재생한다.

지정한 피격 Montage의 원본 Sequence는 Enable Root Motion=false였다. 원본을 바꾸지 않고 `AS_HitReaction_Front`로 복제해 활성화하고, 복제 Montage `AM_HitReaction_Front`가 이를 사용한다. 길이는 0.75초다. Enemy는 기본 CMC로 이동하며 Impulse·Launch·래그돌·피격 중 위치 강제 보정을 사용하지 않는다.

## 코드 및 재생성

- `Source/GE_AIReplication/RootMotionHitWall`: Player 입력·서버 RPC, Enemy 피격 multicast, Notify State, 에디터 애셋 설정 도구.
- `Scripts/GenerateHitWallAssets.py`: Unreal Python commandlet으로 전용 Blueprint·입력·맵 생성. 기존 생성 맵/Blueprint가 있으면 보존을 위해 중단한다.
- `HitWallAssetSetup.prepare_animation_assets()`: 생성 애니메이션·Notify·Slot을 코드의 설정으로 다시 구성한다. 수동으로 수정한 생성 애니메이션의 설정을 덮어쓸 수 있으므로 반복 실행 전 확인한다. 공유 Skeleton에서는 동일 이름 Socket이 없을 때만 추가한다.
- `Scripts/TestHitWall.ps1`: Editor 빌드 후 실행. 작업별 Saved 폴더와 README를 만들고 벽/무장애/입력 예약/전용 서버+클라이언트 기능을 확인한다. 기본 네트워크 포트는 7789, 필요하면 `-Port`로 변경한다.

서버가 공격 순번과 명중을 결정하며 각 재생은 ID로 중복 방지한다. Dedicated Server의 pose/bone tick을 유지한다. 늦은 접속 중 Montage 복구, 대규모 적 tick 최적화, 지연 환경 정량 비교는 후속 작업이다. 현재 검증은 headless 실행으로, 화면의 블렌딩 품질과 카메라 구도는 에디터에서 추가 확인할 수 있다.
