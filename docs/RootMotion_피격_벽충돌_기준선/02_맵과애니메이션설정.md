# 02. 맵과 애니메이션 설정

2026-11-02 KST 갱신. 전용 맵·BP와 단일 피격 에셋은 이미 생성되어 있다. 아래는 **정량 기준선 수집 전 확인·고정할 설정**이다. 현재 실행과 원본 에셋의 관계는 [04](04_공격피격_실행.md)를 따른다. 현재 복제 피격 Montage는 0.75초이며, “긴 피격”의 지속 시간·후방 변위는 pilot에서 별도로 확정한다.

## 1. 새 레벨과 배치

현재 맵은 `/Game/RootMotionHitWall/Maps/L_HitWallBaseline`이다. 생성 스크립트에는 바닥·벽·Enemy·PlayerStart·조명이 있다. Trial Manager와 고정 관찰 카메라, W0~W3 자동 배치는 추가할 항목이다. 생성 스크립트의 고정 벽 위치를 L 기반 조건으로 이미 제어하고 있다고 가정하지 않는다. 기존 기본 맵/Lv_Jang을 덮어쓰지 않는다.

수평 배치 예:

```text
월드 -X                                         월드 +X
Player(+X를 봄)  → 공격 →  Enemy(-X를 봄)  → 뒤로 이동 → 벽
```

- Enemy Capsule 중심의 XY를 (0,0)으로 잡고 높이는 Capsule half-height와 바닥에 맞춘다.
- 벽 앞면 X는 `EnemyCenterX + CapsuleRadius + WallGap`이다. WallGap은 **Capsule 표면부터 벽까지의 거리**이며 중심 거리와 혼동하지 않는다.
- 벽은 높고 충분히 넓게 만들어 초기 실험에서 벽 위·옆으로 빠지는 경우를 줄인다. 벽 두께와 Box extent도 고정·기록한다.
- Player는 Enemy 앞쪽에 배치하고 두 Capsule 사이에 여유를 둔다. 초기 공격 범위가 실제로 Enemy에 도달하는지 debug sweep으로 확인한다.
- 초기 Capsule overlap이 있으면 준비를 실패시킨다. 겹쳐서 시작하는 별도 견고성 실험은 첫 평가에 섞지 않는다.
- Player가 공격 후 Enemy를 계속 밀지 않도록 입력을 잠그고 배치상 충분한 간격을 유지한다.

## 2. 긴 피격 Montage 한 개 확정

현재 실행 에셋은 `/Game/RootMotionHitWall/Animations/AM_HitReaction_Front`이며, Root Motion을 활성화한 복제 Sequence를 사용한다. 아래는 최초 선정 시 참조한 원본 후보 경로다. 현재 에셋을 유지할지 교체할지는 L/T와 접촉 관찰 시간 검증으로 결정한다.

```text
/Game/Sword_Anims/Animations/HandsomeSwordV2/Manny_UE5/RootMotion/Hit/AM_HitReaction_Front
/Game/Sword_Anims/Animations/HandsomeSwordV2/Manny_UE5/RootMotion/Hit/AM_HitReaction_Back
```

관련 Big_Hit_Front/Back Animation Sequence 파일도 존재한다. **정면에서 맞고 뒤로 이동하는 것**을 Editor에서 확인한 뒤 하나만 선택한다.

확인·기록 항목:

1. Skeleton/리타기팅이 실제 Enemy Mesh와 호환되는가?
2. Root Motion이 추출되어 Capsule이 실제로 뒤로 이동하는가?
3. 시작 Section부터 자연 종료까지 T초와 실제 뒤쪽 최대 이동 L은 얼마인가?
4. 루트 회전·의도적인 점프·회전 후 원위치 복귀가 있는가?
5. Montage 슬롯이 AnimGraph의 Slot 노드와 일치하는가?
6. 한 번의 재생이며 loop/다른 Section 반복/중복 Notify가 없는가?
7. blend-in/out, root lock, 재생 속도와 애니메이션 변경 이력이 고정되어 있는가?

여기서 '긴 Montage'는 지속 시간뿐 아니라 **벽까지 이동할 만큼의 후방 Root Motion**이 있어야 한다. 뒤쪽 변위가 거의 없다면 긴 재생 시간만으로 실험 조건을 만족하지 못한다. 후보를 바꾸거나 실험용 복제 에셋을 준비하되, 여러 번 재생해 한 번의 긴 피격처럼 만들지 않는다.

L은 무장애 서버 실행에서 `max(dot(CapsulePosition(t)-StartPosition, InitialBackwardDirection))`로 측정한다. 루트 총 이동거리나 최종 순변위와 다른 값이다. 후보에 의도적인 큰 수직 이동이 있으면 주 기준선에서는 다른 지상 후보를 우선한다. 유지할 경우 수직 상승을 전부 충돌 오류로 집계하지 않는다.

## 3. AnimBP·Enemy 설정

- Animation Sequence의 Enable Root Motion을 확인한다.
- Enemy AnimBP의 Root Motion Mode는 Root Motion from Montages Only로 둔다.
- 간단한 Idle → Slot → Output 구성을 사용하고 피격 재생을 덮어쓰는 다른 슬롯/몽타주가 없는지 확인한다.
- Capsule 중심과 Mesh 기본 상대 위치를 기록한다. root bone/골반의 자세 이동과 Capsule 이동은 구분한다.
- Character: Replicates=true, Replicate Movement=true.
- CMC: Walking, 기본 충돌·중력·smoothing 유지. 세션 시작 시 실제 설정값을 로그로 확인한다.
- Capsule은 벽을 Block한다. Mesh의 추가 blocking·물리 시뮬레이션은 끄고 첫 실험을 시작한다. 벽에 맞는 물리는 Capsule 하나로 제한한다.
- step-up, walkable floor, depenetration 설정은 우선 기본값을 기록한다. 증상을 줄이려고 거리 조건마다 값을 바꾸지 않는다.
- Spline/StateTree/이동 입력/회전 추종이 피격 이동을 덮어쓰지 않게 한다.
- Dedicated Server에서도 애니메이션 평가가 실제로 진행되어야 한다. 초기 진단은 Mesh tick 활성화와 Visibility Based Anim Tick Option의 Always Tick Pose and Refresh Bones를 사용하고, 최적화 설정과 비용을 기록한다. update-rate 최적화는 우선 끈다.

공식 문서: [Root Motion](https://dev.epicgames.com/documentation/en-us/unreal-engine/root-motion-in-unreal-engine), [AnimBP Root Motion Mode](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-editor-in-unreal-engine).

## 4. 벽 거리 조건

[07의 B0](07_단계별작업과평가.md)에서 잰 후방 최대 변위 L을 사용한다. L이 매우 작으면 비율 조건을 만들기 전에 후보부터 재검토한다.

| 조건 | 배치 | 확인 목적 |
|---|---|---|
| W0 | 벽 없음 | 정상 Root Motion과 네트워크 오차의 기준 |
| W1 | WallGap=1.2L 이상 | 벽이 있지만 닿지 않는 대조군 |
| W2 | WallGap=0.5L | 피격 중간에 실제로 벽에 막히는 조건 |
| W3 | WallGap=max(5cm,0.1L), 단 L보다 작게 | 벽에 가까운 피격 조건 |

비율과 함께 실제 cm도 기록한다. 각 Trial에서 같은 설정인지 Manager가 검사한다. 공간 부족 자체는 시작 실패가 아니다. 초기 겹침·바닥 누락·잘못된 자원은 시작 실패다.

## 5. 실행 조건

1. Standalone로 W0/W2를 확인한다. 서버 자체의 상승·밀림과 애니메이션 오류를 먼저 분리한다.
2. Dedicated Server 1개 + Client 1개로 같은 장면을 실행한다. Player는 클라이언트 소유, Enemy는 서버 소유/클라이언트 Simulated Proxy다.
3. N0는 인위적인 지연·지터·손실 없음이다.
4. N2는 기존 프로필처럼 각 방향 Lag=50ms, Jitter=±10ms, Loss=1%를 시작값으로 사용한다. incoming/outgoing 실제 적용 인자를 보관하고 RTT와 편도 설정을 혼동하지 않는다.
5. 서버/클라이언트 60fps를 시작값으로 사용하고 실제 frame time/tick rate를 기록한다. Enemy Actor 빈도와 smoothing은 W0~W3에서 동일하게 유지한다. 기존 Player BeginPlay의 60/30Hz 설정이 Enemy에 자동 적용된다고 가정하지 않는다.
6. 접속·에셋 준비·시작 위치 안정화 후 공격한다. 서버/클라이언트의 TrialId·ReactionId를 확인한다.
7. Montage 종료와 관찰 tail 후 저장을 확인하고 다음 Trial로 넘어간다.

PIE Listen Server는 기능 확인용으로 사용할 수 있으나 Dedicated Server 결과와 구분한다. 최종 화면 측정은 렌더링을 켠 클라이언트에서 한다. 두 번째 observer 클라이언트는 첫 단계 필수는 아니며 복제가 안정화된 후 추가한다.

## 6. 화면에 함께 표시할 디버그 정보

- Role, TrialId/ReactionId, 상태.
- Montage 이름·현재 track time·재생 여부.
- Capsule Z / Mesh Z / WallGap.
- 서버가 확인한 Hit/WallContact 시각과 클라이언트의 수신·재생 시각.
- Enemy Capsule, 벽 collision, 공격 sweep.

콘솔 `show collision`로 Capsule과 Mesh를 구분해서 확인할 수 있다. 화면에 표시되는 서버 좌표는 디버그 데이터이며 추가 복제 비용이 발생하므로 측정 실행에서는 debug replication을 끄거나 별도로 표시한다.
