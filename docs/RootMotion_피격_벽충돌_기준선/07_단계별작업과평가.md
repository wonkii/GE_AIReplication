# 07. 단계별 작업·비교 실험·완료 기준

기준일: 2026-11-02 KST. 아래 단계는 앞으로의 작업 분할이다. 현재 통과한 것은 [01](01_구현계획.md)의 기존 기능 검사이며, 기준선 수집과 연구 평가는 남아 있다. 기간은 **1인 작업량의 초기 추정**으로 일정 확약이 아니다.

## 1. 개발 순서와 완료 관문

2026-11-08 추가: B0 에셋 조사부터 [08의 관절 추출·PELT 분석 도구](08_관절추출_PELT_개발계획과테스트.md)를 사용할 수 있다. `AnimAnalysis.Run`으로 만든 궤적·구간·Library 초안을 I1/I2에 재사용한다. 초안 생성은 I1 후보 선택이나 I2 실제 Warp 실행 검증의 완료를 뜻하지 않는다.

| 단계 | 우선순위/작업량 | 개발·산출물 | 다음 단계로 넘어가는 조건 |

현재 기능 위에서 **기준선 완료까지 약 5~9 작업일**, 이후 개선·연구 평가 **약 23~36 작업일**을 초기 추정으로 둔다. 합계 약 28~45 작업일이다. 단계별 범위를 반올림한 수치이며, 에셋 제작과 owner 엔진 디버깅에 따라 다시 산정한다. Legacy의 27~41일 추정과 단순 합산하지 않는다. 동적 장애물과 연쇄 충돌은 별도다.

I3에서는 owner의 native Root Motion 기준선을 먼저 확인하고 새 계획 필드를 연결한다. owner 경로가 불안정하면 원인을 해결하거나 연구 주장 범위를 줄인다. AI 결과만으로 owner 검증 완료를 선언하지 않는다.

## 2. 기준선 조사: 지금 수집할 조건

L은 무장애 서버에서 시작 후방 방향으로 투영한 **최대 Capsule 변위**, T는 지정 Section/재생 속도의 실제 지속 시간이다. 벽 간격은 Capsule 표면부터 잰다. 배치 상세는 [02](02_맵과애니메이션설정.md)를 따른다.

| 조건 | 벽 간격 | 목적 |
|---|---|---|
| W0 | 벽 없음 | 정상 추출·이동·기본 복제 |
| W1 | 1.2L 이상 | 벽이 있지만 접촉하지 않는 대조 |
| W2 | 0.5L | 피격 중간 벽 접촉 |
| W3 | max(5cm, 0.1L), L보다 작게 | 가까운 벽. 조건 성립 여부를 pilot에서 확인 |

N0는 인위적 지연·지터·손실 없음이다. N2는 기존 프로필의 각 방향 지연 50ms·지터 ±10ms·손실 1%를 시작값으로 쓴다. incoming/outgoing 적용 인자와 실제 관측값을 기록하고 이 값을 RTT라고 부르지 않는다.

수집 전 연결 검증·L/T pilot·N0 W0/W2 각 3회를 수행한다. 다음 조사 수집은 네트워크 W0~W3 × N0/N2 × 10회 = **80 episodes**, Standalone W0~W3 × 5회 = **20 episodes**다. pilot/기능 검사 횟수는 여기에 포함하지 않는다. 이 반복 수는 첫 조사용이며 연구 우위의 최종 표본 수가 아니다.

## 3. 연구 비교군과 효과 분리

모든 군은 정상 Montage 재생 전달, 기본 CMC 충돌·correction, 같은 collision profile·입력 잠금·공격/피격 규칙을 유지한다. F/E의 4개 군은 **같은 안전 planner·Warp 제약·fallback 구현**을 사용한다. U에는 추가 사전 Warp/후보 선택을 넣지 않는다. 모든 군의 행동 식별과 실행 문맥은 기록한다.

| 군 | 후보 선택 | 실행 목표/제약/벽 전환 | 역할 |
|---|---|---|---|
| U: UnrealNative | 고정 후보 | 기본 Montage·CMC 충돌/복제 | 정상 엔진 기준선 |
| F-L: FixedLocalPlan | 고정 후보 | 같은 planner를 각 실행 지점의 현재 상태로 평가 | 안전 실행의 실용 기준선 |
| F-S: FixedSharedPlan | 고정 후보 | 서버 확정 목표/제약/phase 공유 | 고정 동작에서 공유 효과 |
| E-L: EnvLocalPlan | 서버가 환경별 선택, 후보 ID 공유 | 실행 목표/제약/벽 전환은 각 지점에서 평가 | 선택과 공유 효과 분리 |
| E-S: EnvSharedPlan | 서버가 환경별 선택 | 서버 확정 목표/제약/phase 공유 | 제안 방식 |

LocalPlan도 정상 재생·CMC 복제를 사용한다. 서로 다른 Montage를 클라이언트가 제멋대로 고르게 하거나 baseline 복제를 누락해 비교하지 않는다. 피격 강도·damage·경직 정책은 공통이고 로컬 planner는 권위 damage를 만들지 않는다.

| 비교 | 판단할 내용 |
|---|---|
| F-L vs U | 사전 검사·안전 실행 자체의 효과 |
| E-S vs F-S | H1: 공유 조건에서 환경별 후보 선택의 추가 효과 |
| F-S vs F-L, E-S vs E-L | H2: 같은 후보 조건에서 실행 계획 공유의 추가 효과 |
| E-S vs U | 전체 개선. 이 비교만으로 각 기능의 기여를 주장하지 않음 |
| 실제 비용을 맞춘 위 비교 | H3: 네트워크 예산 안에서 개선 유지 여부 |

접촉 Burst·추가 ForceNetUpdate 정책은 주 비교 뒤 별도 실험으로 둔다. 주 방법에만 고빈도 전송을 더해 선택/공유 효과와 섞지 않는다.

## 4. 소유 플레이어 주 평가와 확장 조건

주 평가는 서버 1 + 독립 클라이언트 2, 피격자 Autonomous Proxy와 관찰자 Simulated Proxy를 동시에 기록한다. 서버 AI 기준선의 W 조건과 플레이어 주 평가의 S 조건은 대응 관계가 있어도 역할·데이터 버전이 다른 실험으로 보관한다.

| 장면 | 내용 |
|---|---|
| S0 | 장애물 없는 평지 |
| S1 | 뒤쪽 벽, BackLong 실행 공간 충분 |
| S2 | 뒤쪽 벽, 실행 공간 부족 |
| S3 | 거의 벽에 붙음. 초기 overlap은 없음 |
| S4 | 비스듬한 벽/피격 |
| S5 | 두 벽 코너 |
| S6 | 연속 피격·교체·취소 |

네트워크는 N0/N2 외에 N3=(각 방향 100ms, ±20ms, 5%), N4=(각 방향 250ms, 지터 0, 10%)를 사용한다. 강한 조건에서의 invalid·disconnect도 보고한다.

- 기능 pilot: U/E-S × S0~S3 × N0/N2 × 3회 = 48 episodes.
- 주 평가 초기안: 5개 군 × S0~S3 × N0/N2/N3 × 20회 = **1,200 episodes**.
- 견고성 초기안: 5개 군 × S4~S6 × N0/N2/N4 × 10회 = **450 episodes**.
- 반복 수는 pilot 분산으로 평가 전에 확정한다. 튜닝용 seed/장면과 최종 평가를 분리한다.
- 군 순서를 균형 있게 배치하고 Trial 순서를 seed로 섞는다. 네트워크 난수의 완전한 동일 재현은 가정하지 않는다.

episode는 처음에 12초 고정 창(안정화 2초·피격/회복·tail 포함)으로 pilot한다. 가장 긴 후보와 느린 수신의 종료를 덮는지 확인하고 모든 군에서 같은 창으로 동결한다. 공격 전·접촉 전후·종료 후 구간도 따로 집계한다.

## 5. 동일 네트워크 비용의 정의

설정 NetUpdateFrequency와 실제 전송량은 다르다. 비용은 **고정 episode 창에서 서버 각 연결의 Out+In byte 차분 합계**로 정의한다. 양 끝의 카운터를 더해 같은 전송을 두 번 세지 않는다. server→owner, owner→server, server→observer 방향별 값과 전체를 함께 보고한다.

custom plan/RPC뿐 아니라 CMC move, Root Motion, ACK/재전송이 반영되는 연결 비용을 측정한다. connection bytes·NetTrace actor bits·NIC bytes는 범위가 다르므로 같은 단위의 값으로 섞지 않는다. counter reset/연결 교체도 기록한다.

1. 평가와 분리한 calibration 장면/seed에서 각 군의 실제 비용을 잰다.
2. 예: 60fps, 기본 Actor 갱신 10Hz, 추가 Burst 없음에서 시작한다. 실제 tick·fps·move cadence를 기록한다.
3. 공통 Actor 빈도 후보 5/10/20/30Hz 등을 적용해 비용–품질 곡선을 만든다. owner move cadence는 주 비교에서 공통으로 유지한다.
4. 겹치는 비용 지점을 골라 설정을 동결하고 목표 비용 **±5%**를 초기 허용 폭으로 둔다.
5. 최종 실행의 예산 초과도 보고한다. 결과가 좋은 Trial만 골라 비용을 맞추지 않는다.
6. 겹치는 구간이 없으면 동일 비용 비교를 판단불가로 표시하고 Pareto 곡선을 제시한다. padding이나 correction 비활성화로 비용을 맞추지 않는다.

## 6. 지표·통계·행동 품질

세부 계측 경계는 [03](03_측정과완료기준.md), 신규 계획/replay 필드는 [06](06_후속개선_상세설계.md)을 따른다.

| 영역 | 주요 지표 |
|---|---|
| 충돌 | Capsule blocking overlap 비율/시간, 알려진 벽 기하의 깊이, 시각 bone proxy 침투 |
| 비의도적 상승 | Capsule bottom의 무장애/허용 수직 이동 대비 초과 높이 peak·시간 |
| owner 보정 | correction 수신과 replay 후 현재 위치 변화를 분리, 큰 보정 episode 비율 |
| observer 보정 | Root Motion fixup/SmoothCorrection·Mesh 튐, owner RPC와 별도 |
| 동기화 | 명중→첫 반응 지연, Montage phase 차이, 같은 실행의 서버 궤적 오차 |
| 행동 품질 | 요청 대비 밀림 거리/방향, InPlace/fallback율, 회복 시간, 발 미끄러짐 proxy |
| 비용 | bytes/episode·bytes/s·packets/s, planner/sweep CPU 평균/p95, 기록 오버헤드 |

초기 큰 보정 표시는 20cm, 상승 표시는 5cm/0.1초를 사용하되 pilot에서 동결한다. correction 10/20/40cm 민감도와 원시 연속값을 보존한다. 정상 Root Motion 이동을 화면 보정으로 전부 계산하지 않는다. 영상 없이 headless 데이터만으로 블렌딩 자연스러움을 결론내리지 않는다.

프레임을 독립 표본으로 세지 않고 **episode를 통계 단위**로 한다. 같은 seed/장면을 대응시킨 비교와 episode bootstrap 신뢰구간을 사용한다. 평균·p95·최악값·실패율·절대 차이를 보고한다. 같은 PC는 UTC wall clock과 server time을 함께 기록하고 다른 PC는 시계 오차를 먼저 측정한다.

## 7. 품질 검사와 성공·수정 기준

기술적 invalid는 빌드/에셋/schema 불일치, 연결 실패, 잘못된 초기 overlap, 공격 미명중, Montage 재생 실패, 핵심 샘플 누락, 저장 실패 등으로 사전 정의한다. 기술적 실패 자체의 빈도도 군별로 보고한다. **관통·상승·회복 실패는 성능 결과**이므로 invalid로 제거하지 않는다. 동일한 관찰창 정책을 유지하고 부족한 tail 원본도 보존한다.

초기 연구 목표는 E-S가 F-S 등 사전 선정한 강한 실용 기준선 대비, 동일 비용에서 큰 보정 episode 비율을 30% 이상 줄이는 것이다. **30%는 논문이 보장한 수치가 아니라 pilot 후 확정할 프로젝트 목표**다. 다음 조건을 함께 본다.

- Capsule 관통/상승을 악화시키지 않고, 밀림·시작 지연·회복 품질의 사전 허용 범위를 지킨다.
- 효과 크기·신뢰구간·기준선 발생률을 함께 보고한다. 기준선 사건이 거의 없으면 상대 감소율을 과장하지 않는다.
- F-L만으로 충분하면 안전 실행으로 해결되었다고 판단하고 후보 선택/공유의 추가 효과를 제한적으로 서술한다.
- 후보 선택만 효과가 있으면 H1과 H2를 별개로 판단한다. owner가 악화되면 observer 개선만으로 성공 처리하지 않는다.
- 비용 구간이 겹치지 않으면 H3는 판단불가다. 문제가 재현되지 않으면 장면·가설을 재검토한다.

## 8. 필요한 검사와 최종 전달물

| 변경 종류 | 필요한 검증 |
|---|---|
| Trial/Recorder | 중복/누락/이전 Trial·flush 실패, reset과 측정창 분리 |
| 후보/점수 | hard constraint·단위 정규화·동점·fallback·허용 scale |
