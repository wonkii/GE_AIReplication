# 12. 다중 벽 자동 순회 실행

2026-11-09 구현. 실제 명령 계약은 이 문서를 따른다. [11번 계획](11_다중벽_자동순회_개발계획.md)의 Profile Asset 대신 기존 마커를 읽는 adapter를 먼저 연결했다. 좌표·지점 이름을 C++에 고정하지 않는다. `IncludeDisabled=1`을 명시하면 `xHitWall_` 태그도 해당 실행에 포함한다. 맵의 태그를 저장하거나 수정하지 않는다.

## 준비

1. 새 C++ 모듈을 반영하도록 현재 Unreal Editor를 정상 종료하고 다시 연다. 저장할 작업이 있으면 먼저 저장한다. 이번 빌드는 열린 Editor의 DLL 잠금 때문에 별도 이름 모듈을 사용했다. 실행 중 Editor에 코드를 강제 hot reload하지 않았다.
2. Content Browser에서 `/Game/YHJ/Lv_HitWallTest` 맵을 연다.
3. 우선 Number of Players=1로 Play한다. Listen Server에서는 host의 게임 콘솔에서 실행하고 host 화면으로 관찰한다. 원격 Client의 카메라 자동 전환은 제공하지 않는다.
4. 게임 화면을 클릭하고 백틱/틸드 키로 게임 콘솔을 연다. 일반 Editor Output Log의 Cmd 입력창은 사용하지 않는다.

## 첫 비교: 아래 순서로 한 줄씩 입력하고 Enter

첫째, 이 PIE 세션에 사용할 Library/실험 정책을 지정한다. 이 명령 자체는 피격을 발생시키지 않는다.

```text
ReactionWarp.Mode MultiPhase AllowDraft=1 Library=/Game/Combat/Analysis/DA_HitReaction_Front_PELT Policy=/Game/Combat/Analysis/DA_ReactionWarp_Front_Draft
```

둘째, 비활성 마커까지 포함해 지점을 검사한다. 현재 YHJ 맵에서는 `Audit: 6 loaded stations`가 나와야 한다. Output Log의 Station 줄에는 장애물, 접촉 법선, 거리가 표시된다. 이 명령은 피격이나 카메라 전환을 하지 않는다. 등록 지점은 현재 월드에서 로드된 태그 Actor 기준이며, 다른 맵에서 예상 지점이 미로드돼 있으면 먼저 해당 영역을 로드해야 한다.

```text
ReactionWarp.Stations IncludeDisabled=1
```

셋째, 여섯 지점에서 Off→MultiPhase를 연속 관찰한다. 처음에는 100cm 한 조건의 12회 순회를 권장한다. 콘솔을 닫으면 카메라와 HUD를 볼 수 있다.

```text
ReactionWarp.Tour mode=MultiPhase baseline=Off gaps=100 reps=1 IncludeDisabled=1 AllowDraft=1
```

이름순 지점 → gap → 반복 → Off/선택 모드 순서다. 각 trial은 준비 대기 1.2초, 피격, 종료 후 관찰 1.5초로 진행한다. 별도 고정 관찰 카메라로 피격자와 장애물을 보여주고 원래 Player를 다시 possess하지 않는다. 종료 시 위치·카메라 view target·입력 잠금·보정 모드/enable/draft·기록 설정·FPS를 복원한다.

## 비교 범위를 늘리는 명령

앞 순회가 완료된 뒤 다음 중 하나를 입력한다. 진행 중 모드를 바꾸려면 먼저 `hitwall.Stop`을 입력한다.

세 거리, Off와 MultiPhase 비교: 여섯 지점×세 거리×두 모드=36개 예정 trial.

```text
ReactionWarp.Tour mode=MultiPhase baseline=Off gaps=120,100,80 reps=1 IncludeDisabled=1 AllowDraft=1
```

전체 동일 배율과 기본 충돌 비교:

```text
ReactionWarp.Tour mode=Uniform baseline=Off gaps=120,100,80 reps=1 IncludeDisabled=1 AllowDraft=1
```

가운데 구간만 보정:

```text
ReactionWarp.Tour mode=MiddleOnly baseline=Off gaps=120,100,80 reps=1 IncludeDisabled=1 AllowDraft=1
```

선택 보정만 여섯 지점에서 재생:

```text
ReactionWarp.Tour mode=MultiPhase baseline=None gaps=100 reps=1 IncludeDisabled=1 AllowDraft=1
```

기본 충돌만 관찰:

```text
ReactionWarp.Tour mode=Off baseline=None gaps=100 reps=1 IncludeDisabled=1
```

순회 제어는 각각 한 줄씩 입력한다. Pause는 현재 피격/tail이 끝난 뒤 다음 시험 진입을 보류한다. 재생 속도나 전체 월드 시간을 바꾸지 않는다.

```text
ReactionWarp.TourPause
```

```text
ReactionWarp.TourResume
```

```text
hitwall.Stop
```

`camera=0`을 Tour 명령 끝에 붙이면 자동 카메라와 입력 잠금을 사용하지 않는다. `IncludeDisabled=1`을 빼면 기존 활성 `HitWall_`만 사용하므로 현재 맵에서는 Ledge30 한 곳이다. `AllowDraft=1`은 세션 실험용이며 Asset 승인 상태를 바꾸지 않는다.

## 결과 읽기

- HUD: 진행률, station, 요청 gap, 요청 mode, 준비/계획 결과와 이유. `Fallback`은 기존 CMC 이동으로 돌아간 결과다. `Unmodified`는 원본 유지이며 보정이 적용됐다는 뜻이 아니다.
- floor/overlap, 다른 장애물, 정착 후 거리 오차(5cm 초과), 부족한 공간은 해당 trial을 Skipped로 기록한다. 큰 gap 하나가 실패해도 작은 gap은 별도로 시도한다.
- `Completed`는 재생 완료다. 발 디딤·충격감·회복·벽 반응의 자연스러움은 화면에서 판단한다. 경사면의 정상적인 지형 상승을 모두 오류로 세지 않는다.
- 매 run은 `Compare artifacts:`로 출력된 `Saved/Tasks/*-reaction-warp-*/`에 저장된다. README부터 읽는다. `trials.csv`의 station 열과 모드·상태·이유·plan hash, `stations.csv`의 지점/장애물/법선, `placements.csv`의 요청/실측 거리를 함께 본다. 실제 발·Capsule은 `runtime_samples.csv`, 원본 계획은 `plan-*.json`이다.
- 일반 수치 보고서는 프로젝트 루트 PowerShell에서 `python Scripts/ReactionWarp/render_report.py '<출력된 작업 폴더>' --open`으로 연다. 기존 네 화면 골격 재생기 `motion_comparison.py`는 여러 station/부분 모드를 지원하지 않으므로 이 자료에 사용하지 않는다.

현재 첫 구현의 범위는 기존 태그 기반 지점 순회와 로컬 관찰 카메라다. Profile Asset, 미로드 World Partition 자동 로딩, 단일 비교 쌍 Replay, 지형별 전용 피격 후보/IK, 원격 Client 카메라 동기화는 후속 항목이다. 서버 계획·Root Motion 복제 방식은 이번 작업에서 변경하지 않았다.

## 수행한 검증

UE 5.8 Editor Development 빌드 통과. 실제 YHJ 맵의 100cm 조건에서 Off/MultiPhase 12 trial을 NullRHI 및 D3D12 offscreen 렌더링으로 각각 실행했고 모두 완료됐다. 각 실행에서 여섯 MultiPhase 계획은 BudgetSolved이며 중간 취소·자연 종료 후 위치/view target/입력 잠금 복원 검사도 통과했다. 시각적 자연스러움의 합격이나 원격 Client 동작을 검증한 결과는 아니다.

재현용 PowerShell 명령(프로젝트 루트, 한 줄씩):

```powershell
./Scripts/TestHitWallTour.ps1
```

```powershell
./Scripts/TestHitWallTour.ps1 -Rendered
```

위 자동 검사는 작업 Editor가 아닌 별도 프로세스를 실행하고 종료한다. 테스트 월드의 Spline 실험 관리자 자동 타이머를 격리하고, 게임 모드에서 오류가 나는 Python 도구 초기화를 `-DisablePython`으로 끈다. 최초 초기화 지연 실행들은 timeout으로 남겼으며 성공 결과와 함께 작업 폴더 README에 기록했다. 사용자 화면에서 자연스러움을 비교하려면 앞의 PIE 콘솔 명령을 사용한다.
