# 기존 계획에서 현재 계획으로의 변경 요약

정리일: 2026-11-02 KST.

## 계획이 바뀐 흐름

| 단계 | 목표와 범위 | 다음 단계로 바뀐 이유 |
|---|---|---|
| 기존 M0~M8 | 서버 AI의 Spline 이동·Impulse 급변을 감지하고 전송 정책·클라이언트 Mesh 예측의 정확도와 비용 비교 | 이동·감지·전송·기록이 연결된 뒤, 실제 캐릭터 충돌과 보정 문제로 관심 확장 |
| Root Motion 연구 전체 계획 | 환경을 고려한 피격 동작 선택과 서버 행동 계획 공유로 관통·상승·큰 Correction을 줄이는지 동일 네트워크 비용에서 검증 | 개선 효과를 비교하기 전에, 현재 기본 동작에서 문제가 얼마나 발생하는지 기준선 필요 |
| 현재 첫 구현 | Player가 Enemy 앞에서 실제 공격 → 서버 명중 확정 → Enemy가 고정된 긴 Root Motion Montage 1개 재생 → 뒤쪽 벽과 기본 CMC 충돌 → 발생량 기록 | 해결 기법을 넣기 전, 재현 가능한 장면과 원본 로그·영상을 확보하는 단계로 축소 |

## 현재 계획에서 달라진 점

- **대상:** 첫 실험의 피격자는 서버 소유 Enemy다. 클라이언트에서는 Simulated Proxy이며, 소유 플레이어 피격의 Autonomous Proxy 실험은 후속으로 둔다.
- **피격 원인:** 기존 Impulse Volume 대신 Player의 정면 공격과 서버의 실제 명중 검사를 사용한다.
- **이동:** 고정된 긴 피격 Montage의 Root Motion만 적용한다. 추가 Impulse·위쪽 Launch·부분 래그돌·Spline 추종을 섞지 않는다.
- **목적:** 문제 해결이나 성능 우위 입증에 앞서 벽 거리·네트워크 조건에 따른 관통·Capsule 상승·Mesh 움직임·proxy 보정을 분리 측정한다. 문제가 0건인 결과도 인정한다.
- **보류한 개선:** Motion Warping, 안전 목표 제한, 다중 후보 선택, WallHit 전환, 행동 계획 공유 최적화, Burst 전송은 기준선 확보 이후에 추가한다.
