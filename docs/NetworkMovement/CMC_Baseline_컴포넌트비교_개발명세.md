# 달리기 상태 전환 네트워크 실험 개발 명세

두 배치 명령은 UE 5.8 에디터의 PIE 클라이언트 콘솔에서 실행한다.

## 변경 범위

- 수동 명령의 `Movement.Sprint Simple`, 자동 시험의 `SprintTrial.Run Simple`, 전용 캐릭터와 보고서·비교 스크립트의 전용 분기를 제거한다. 현재 `SprintTrial.Run Stock`도 서버가 걷기만 하는 동일한 달리기 입력을 검사하므로 이 실험에서 함께 제거한다. 기존 저장 결과는 보관한다.
- 공용 Shift 입력, 속도 결정, 서버 오차 검사, 보정·재생, 원격 계측, 오버레이를 유지한다. `SeparateRpc`와 `MoveData`의 수동 명령과 기존 단일 조건 명령은 계속 지원한다. 기존 `RubberBanding.OwnerTest`의 `Baseline`은 별도 RPC를 쓰는 독립 경로이므로 유지한다.

## 실행 계약

UE 5.8 Development Editor에서 현재 시험할 레벨을 연다. PIE를 **Play As Client**, **Number of Players = 2**, **Run Under One Process**로 시작한다. 원하는 클라이언트에서 평탄하고 전방이 열린 바닥에 멈춘 뒤 게임 콘솔(`~`)에서 한 줄을 입력한다.

| 명령 | 서버에서 달리기 상태를 결정하는 방법 | 실행 수 |
|---|---|---:|
| `SprintTrial.SeparateRpc [Block]` | 소유자가 키 전환마다 Reliable Server RPC를 보내고 서버가 마지막으로 수락한 의도를 사용한다. | 9 |
| `SprintTrial.MoveData [Block]` | 소유자가 각 CMC 저장 이동의 압축 플래그에 의도를 기록하고 서버가 해당 이동 처리 시 읽는다. | 9 |
| `SprintTrial.Close` | 진행 중인 배치를 중단하고 캐릭터와 네트워크 설정을 복구한다. | |

두 명령은 인자 없이 각각 실행할 수 있다. `Block`의 기본값은 1이며 반복 비교 시 두 명령에 같은 번호를 지정한다. 실행 중 다시 시작하는 요청은 현재 배치에 영향을 주지 않는다.

명령을 입력한 클라이언트의 소유 캐릭터를 서버에서 대응시킨다. 서버와 소유자 모두 지상에서 정지해 있을 때 위치를 확정하고, 소유자의 카메라 수평 방향으로 진행한다. 원래 캐릭터와 시험 캐릭터의 캡슐 크기가 다르면 발 위치를 기준으로 맞춘다. 매 조건에 그 위치·방향에 새 시험 캐릭터를 생성하고 명령을 입력한 클라이언트에 소유권을 넘긴다. 해당 PIE 창에서 시작 프레임의 카메라 상대 위치·회전·시야각으로 시험 캐릭터를 따라간다. 다른 창은 기존 시점을 유지하면서 원격 복제를 계측한다. 배치 종료 시 원래 캐릭터·뷰·카메라 방향으로 복구한다.

수동 플레이에는 `Movement.Compare view`와 `Movement.Sprint SeparateRpc` 또는 `Movement.Sprint MoveData`를 사용한다. WASD로 이동하며 Shift를 누르거나 놓으면 된다. `Movement.Sprint Status`는 현재 상태를, `Movement.Compare status`는 위치 비교 결과를 출력한다. `Movement.Sprint Off`는 수동 달리기를 끄고 `Movement.Compare off`는 오버레이를 닫는다. 개별 자동 시험도 `SprintTrial.Run <SeparateRpc|MoveData> [Local|Fixed50|Fixed100|Jitter|Loss] [Straight|Turn90|Toggle] [Block]`으로 실행할 수 있다.

## 네트워크 조건

각 행에서 손실률을 왼쪽부터 한 번씩 적용한다. Jitter는 UE의 송신 패킷 모의 설정 `PktJitter` 값(ms), Loss는 각 방향에서 패킷을 버릴 확률(%)이다. 소유 클라이언트의 송신과 수신에 기본 지연 50 ms를 두며, **지터는 상태 전환이 서버로 전달되는 송신 방향에 적용한다.**

| PktJitter | 클라이언트 → 서버 추가 지연 | 서버 → 클라이언트 추가 지연 | 방향별 손실률 |
|---:|---|---:|---|
| 100 ms | 50 또는 150 ms | 50 ms | 0%, 10%, 20% |
| 200 ms | 50 또는 250 ms | 50 ms | 0%, 10%, 20% |
| 300 ms | 50 또는 350 ms | 50 ms | 0%, 10%, 20% |

UE 5.8은 송신 패킷 번호의 홀짝에 따라 낮은 지연과 높은 지연을 번갈아 적용한다. 지터를 올리면 평균 송신 지연도 증가한다. 각 셀 안에서 두 구현을 대조한다. 서버와 관찰자의 드라이버는 기본 에뮬레이션 설정으로 실행해 소유자 연결에 지연을 이중 적용하지 않는다. 실측 RTT와 실제 패킷 수는 원본에 별도 기록한다.

## 입력과 역할

- 같은 TrialId의 서버 캐릭터, 자율 프록시, 시뮬레이션 프록시가 준비되면 소유자와 서버의 접지 및 실제 이동 전송을 확인한다. 지연 설정을 적용하고 1초 워밍업한 뒤 기록을 시작한다. 준비 확인에는 소유자의 이동 타임스탬프 증가와 서버의 이동 수신을 포함한다. 입력은 소유자에게만 재생한다.
- 같은 방향으로 2초 걷고, 다음 2초 동안 250 ms마다 달리기 의도를 켰다 끈다. 이어서 2초 걷고 2초 정지한다. 서버 응답 수집을 위해 1초 더 기다린다. 시험 캐릭터의 걷기/달리기 상한은 350/650 cm/s다.
- 두 구성은 같은 이동 컴포넌트와 속도 결정 함수, 전환 경계에서 저장 이동 결합 방지, 보정 후 저장 이동 재생을 사용한다. 서버가 수신한 RPC 또는 이동 플래그를 적용하고, 관찰자는 서버의 복제 이동을 수신한다.
- 셀마다 새 TrialId를 사용한다. 시간 동기화, 위치 보정, 패킷 손실 난수는 실제 PIE 실행에 따른다. 각 명령 1회는 조건당 1회 측정이다.

## 기록과 판정

배치 폴더는 `Saved/Tasks/<시각>-SprintMatrix-<방식>-<ID>/`를 사용한다. 먼저 README를 만들고 명령, UTC 시각, 파일 설명, 진행 상태 및 원본 보관 기준을 적는다. 최상위 `batch.csv`에는 계획된 9조건과 각 조건의 실행 여부·결과·실패 사유·결과 폴더를 남긴다. 각 `Jitter100Loss0` 등의 하위 폴더에 다음 파일을 기록한다.

| 파일 | 확인할 내용 |
|---|---|
| `manifest.json` | 배치·시험 ID, 블록 번호, 셀 순번, 방식, 맵·빌드, 시작 좌표·방향, 입력 프로파일, 방향별 지터·지연·손실 설정, 종료 상태 |
| `server/events.csv`, `owner/events.csv` | 서버가 검사한 이동의 끝점과 클라이언트가 보고한 끝점, 소유자 입력·보정·재생 이벤트 |
| `observer/events.csv`, `server/network.csv` | 관찰자 복제 수신·메시 오프셋과 연결별 패킷·바이트 수 |
| `summary.csv` | 같은 이동의 위치 오차 p95(cm), `Transition100P95Cm`, `Press100P95Cm`, `Release100P95Cm`, 속도 상한 불일치, 서버 최고 속도, 소유자 보정 횟수, 대응·누락 표본 수 |

같은 시험의 CMC epoch·move timestamp로 소유자 예측과 서버 이동을 연결한다. 주 지표는 실제 의도가 바뀐 저장 이동부터 **100 ms 또는 다음 전환 직전 중 먼저 오는 시점**까지의 위치 오차 p95다. 누름·해제를 합쳐 주 지표를 계산하고 각각의 값도 기록한다. 해당 구간의 속도 상한 불일치는 대응된 이동 중 두 역할의 상한이 다른 이동의 비율로 기록한다. 대응이 없는 표본과 전환 수는 분모와 함께 별도로 저장한다. 기존 `TransitionP95Cm`은 종전 500 ms 지표로 유지한다.

같은 시작점·방향, 입력, 네트워크 조건과 블록 번호를 가진 두 방식을 짝짓는다. 조건별로 **RPC의 전환 구간 p95 − MoveData의 전환 구간 p95**를 계산하고 전체 이동 p95와 보정 횟수도 함께 보고한다. 비교 스크립트는 두 방식의 셀 폴더를 받아 짝별 차이와 실패·누락 수를 출력하도록 갱신한다. 조건당 한 쌍은 개별 측정값으로 보고한다. 반복 시 RPC 선행과 MoveData 선행을 번갈아 적용하고, 여러 쌍의 결과는 블록 단위 차이의 중앙값과 신뢰구간으로 보고한다.

## 인수 기준

1. **삭제와 회귀 확인**. `Simple`과 `Stock` 진입점 및 전용 분기의 호출부를 제거한다. 남은 두 전달 방식으로 수동 Shift와 개별 시험을 실행해 소유자·서버·관찰자의 동작과 원본 생성을 확인한다.
2. **배치 실행과 복구**. 셀마다 새 시험 캐릭터·타임스탬프로 시작하고 이전 셀의 지연 패킷이 새 시험 캐릭터의 입력에 섞이지 않는지 확인한다. 일부 셀의 경로 이탈이나 기록 실패 후 복구할 수 있으면 실패를 남기고 다음 셀을 시도한다. 연결 종료, PIE 종료 및 명령 취소 때는 배치를 중단하고 완료·미실행 셀을 기록한다. 정상 종료와 실패 시 원래 소유권·뷰·네트워크 설정을 복구한다. 짧은 달리기 구간에서 최고 속도에 도달하지 못한 결과도 표본에 포함한다.
3. **품질 확인**. 두 명령으로 18조건을 실행하고, 클라이언트 2에서도 명령을 실행해 소유권이 지정한 창으로 가는지 확인한다. 각 배치에서 9개 조건, 동일 발 위치·진행 방향, 올바른 카메라, 세 역할의 기록과 종료 후 복귀를 검증한다. 중복 요청, 중간 취소 및 취소 후 재실행을 검사한다. 한 셀을 골라 서버·소유자 원본에서 누름·해제 지표를 재계산하고, 같은 표본이 두 전환에 중복 배정되지 않는지 확인한다.

초기 PIE 시도에서 시험 캐릭터가 자율 프록시로 복제되고 RPC가 서버에 도달한 뒤에도, 소유자의 이동 타임스탬프가 0에 머문 실행이 있었다. 준비 단계의 이동 송수신 확인에는 이 사례를 포함한다. 시간 초과 로그에는 서버·소유자·관찰자의 역할, 소유권 승인 여부, 이동 모드와 마지막 이동 타임스탬프를 남긴다. 접지 이탈과 과도한 프레임 지연은 각각 기록해 경로 문제와 시험 환경 문제를 식별할 수 있게 한다.
