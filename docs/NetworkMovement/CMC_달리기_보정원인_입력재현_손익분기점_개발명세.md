# CMC 달리기의 보정 원인, 입력 재현성과 전송 비용 손익분기점

2026-11-23 · GE_AIReplication · UE 5.8.3 · 다음 구현을 위한 명세

**목표는 서버 권한과 기존 보정 판정을 유지하면서, 같은 이동에 서로 다른 달리기 의도나 속도 상한을 적용해 생기는 오차를 찾아 줄일 수 있는 범위를 측정하는 것이다.** 시험 대상은 소유자→서버의 지상 걷기·달리기 전환이다. 서버·소유자·관찰자 기록을 수집하고, 숫자 하나에서 해당 이동과 원시 이벤트까지 역추적할 수 있게 한다. 구현 순서는 **기존 기록 재분석 → 새 Tap 계측 → 별도 프로세스 비용 실험**이다.

## 출발점과 비교 대상

| 구현 | 같은 Shift 의도를 전달하는 경로 | 이번에 밝힐 점 |
|---|---|---|
| SeparateRpc | 누름·해제마다 Reliable 서버 RPC. 서버는 마지막으로 수락한 요청과 달리기 허용 조건을 사용한다. | RPC를 보낸 시점, 서버가 처리한 시점, 실제로 어느 이동에 적용했는지가 얼마나 다른가? |
| MoveData | 저장 이동의 기존 압축 플래그에 의도 저장 | 중요 이동으로 선택돼 동봉된 OldMove가 짧은 입력 재현과 비용에 주는 영향은 얼마인가? |
| MoveDataBit | 같은 저장 이동에 독립 1비트 직렬화. 전환 경계의 이동 결합 제한과 재생 시 의도 복원은 MoveData와 공유한다. | 레코드마다 비트를 보내는 비용이 어느 전환 빈도에서 회수되며 짧은 입력의 누름과 해제가 모두 재현되는가? |

기존 단일 프로세스 PIE 결과는 지터·손실 9조건 × 3패턴 × 3방식, 셀당 한 블록이다. MoveDataBit의 SeparateRpc 대비 전체 양방향 이동 RPC 콘텐츠 변화 중앙값은 Toggle −3.3%, Hold −7.1%, Tap −2.0%였다. Tap 적용 구간 겹침은 두 이동 데이터 방식 각 9/9, SeparateRpc 4/9였다. 이 수치는 기존 집계를 재현하는 기준으로 사용한다. 예를 들어 SeparateRpc의 지터 200ms·손실 10%에서는 서버의 누름·해제 처리 시각이 743.635830656초와 749.286804158초였다. **5.651초는 두 핸들러의 서버 시각 차이**다. 새 보고서에서는 실제 달리기 적용 시간, 응답 지연, 이동 거리를 각각 산출한다. ## 1단계 · 보정 한 건에서 원시 이동까지 추적

1. 기존 `SprintTrial.Run ProfileReport <배치폴더명>`에 진단 보고서 생성을 추가한다. 기존 `manifest.json`, 역할별 `events.csv`, `packed.csv`, `timing.csv`, `rpc_bits.csv`, 필요 시 원본 추적을 읽어 새 작업 폴더에 쓴다. 새 열이 없는 기록에서도 대응 가능한 행을 출력한다. 예전 `OwnerMove`, `ServerAppliedMove`, `ServerCheck`, `OwnerCorrection`이 제공하는 값과 새 계측값을 필드별로 구분한다. 예전 SeparateRpc의 이동 플래그 0으로 서버 의도를 추정하지 않는다.
2. 이동 키는 시험 ID·시험 캐릭터·timestamp epoch·CMC 원본 이동 timestamp다. 새 기록은 timestamp의 원본 float 비트 또는 왕복 복원 가능한 정밀도를 보관한다. 역할 간 로컬 포인터, 프로세스 프레임 번호, 반올림된 월드 시각은 조인 키로 쓰지 않는다. epoch 경계, 이동 결합, OldMove 재동봉, 중복 수신, 실제 적용, 재생을 구분한다. 여러 번 직렬화된 같은 이동은 송신 비용에는 각각, 실제 적용·최초 예측에는 각 고유 이벤트로 센다. 모호한 대응은 후보 수와 사유를 남긴다.
3. 시험용 이동 컴포넌트와 기존 버퍼를 확장해 아래 이벤트를 수집한다. 로컬 캡처와 NetTrace를 사용한다. 측정용 식별자나 시각을 게임의 이동·상태 RPC 페이로드에 추가하면 비용 비교가 달라진다. 기존 서버 허용 정책, 350/650cm/s, 중요 이동 선택, 엔진의 보정 임계값과 빈도 제한을 세 방식에서 유지한다. [이동 및 보정 훅](../../Source/GE_AIReplication/Measurement/SprintTrialCharacter.cpp) · [기존 조인·집계](../../Source/GE_AIReplication/Measurement/SprintTrialReport.cpp)

| 관측 지점 | 새 기록의 필수 값 |
|---|---|
| 소유자 | 입력 에지와 실제 입력 시각, 최초 예측·재생 구분, 저장 의도, 물리 계산에 적용된 속도 상한·packed movement mode, 이동 시작·끝 위치, CMC 이동 시간·delta, 현재 ACK. 결합 전 기록과 실제 전송 레코드를 구분한다. |
| 서버의 달리기 정책과 이동 | RPC 수신 요청·순번·수락/거부 및 사유, 해당 이동이 읽은 의도와 출처, 지상·웅크림에 따른 허용 여부, 실제 속도 상한, 시작·끝 이동 모드/위치, delta. 요청 수신과 이동 적용을 별도 행에 쓴다. |
| 서버 검사·응답 | 서버 위치와 클라이언트 보고 위치, 위치 오차, 양쪽 packed movement mode, 실제 검사 반환값, 관측 가능한 강제 보정 여부, 응답 생성·송신·대상 이동·ACK/보정 종류. 훅에서 확인할 수 없는 내부 분기에는 추정 표시 또는 NA를 쓴다. |
| 소유자 수신·재생 및 관찰자 | 응답 수신과 실제 보정 적용, 재생 이동 수·CPU 시간, 적용·재생 전후 위치 변위. 여러 응답이 한 번의 재생으로 모이면 묶음으로 연결한다. 관찰자 메시 오프셋·갱신 간격은 별도 열로 남긴다. |

**귀속 규칙.** 동일 이동에서 의도 불일치, 속도 상한 불일치, 엔진 이동 모드 불일치, 위치 기준 초과를 독립 열로 남긴다. 첫 상한 불일치와 그 직전의 대응 이동, 누적 위치 오차, 상한이 다시 일치한 이동, 후속 검사·응답·소유자 보정을 한 구간으로 연결한다. 구간은 해당 이동에 대한 재동기화가 확인되거나, 양측 상한·모드가 일치하고 위치 오차가 허용 범위에 복귀할 때 닫는다. 다음 불일치가 겹치면 구간을 병합하고 보정당 대표 구간 하나를 둔다. 중간 이동이 사라졌으면 공백을 표시한다. 보정 시점의 상한이 같아도 앞서 시작한 구간을 찾는다.

보고서에는 **같은 이동에서 불일치 관측 / 선행 불일치 후 보정 / 다른 판정 근거 관측 / 근거 부족**을 구분하고, 여러 근거가 겹치면 모두 보존한다. 단지 시간상 인접한 사례로 원인을 확정하지 않는다. 조건별로 불일치 이동 수/대응 이동 수, 각 분류별 건수/소유자 수신 보정 수, 위치 오차·보정 후 변위 p95(cm), 대응 누락률을 제시한다. 판정 근거가 확인된 범위와 미확인 건수를 함께 제시해야 “남은 보정 중 달리기 의도 전달로 개선할 여지”를 해석할 수 있다.

**인수 기준.** 구버전 한 셀에서 기존 보정 건수를 재현하고 원본 행으로 돌아갈 수 있다. 새 기록에서는 직접 불일치, 선행 불일치, 불일치 증거가 없는 보정과 응답만 작성된 경우를 서로 구분할 수 있다. ACK·보정 작성·송신·수신·재생의 건수는 각각 검산하고, 손실·병합·미대응 때문에 달라지는 수를 표시한다. 0건과 수집 불가는 다른 값이다.

## 2단계 · 짧은 입력이 서버에서 언제 시작하고 끝났는지 검증

- 기존 소유자 콘솔의 `SprintTrial.<방식> <블록> Profile <패턴>`을 확장한다. 현행 `Toggle`, `Hold`, `Tap`의 타이밍과 기본값을 보존한다. 새 패턴 `TapSweep`은 50·100·200ms 탭과 100ms 누름 두 번(사이 해제 100ms)을 각각 독립 시행한다. 각 시행의 시작은 걷기이며 동일한 전방 입력을 쓴다. 다음 시행은 이전 해제 관측 또는 타임아웃 후 새 시험 캐릭터·캡처에서 시작한다. 기존 지터 100/200/300ms × 양방향 손실 0/10/20% 행렬을 재사용한다. 같은 네트워크 셀 안에 시행 ID와 입력 순번을 둔다.
- 예약한 에지, 실제 입력 프레임, **의도가 바뀐 최초 저장 이동**, 실제 서버 적용 이동을 따로 기록한다. 짧은 입력 전체가 한 프레임 안에 지나가 최초 예측에 남지 않은 경우도 결과로 남긴다. RPC 송신 시도·재전송·핸들러 처리에는 기존 전환 순번과 확인 가능한 액터 채널·Reliable bunch 순번·패킷 범위를 사용한다. 패킷 ID만으로 RPC의 재전송이나 도착을 단정할 수 없으면 미귀속으로 둔다.
- 1차 판정은 양쪽이 공유하는 CMC 이동 시간축에서 한다. 소유자의 누름 시작 이동부터 해제 시작 이동까지를 반열린 구간으로 정의한다. 서버는 실제로 소비한 이동의 의도, 허용 조건, 적용 상한과 delta로 달리기 구간을 복원한다. timestamp가 이동 끝을 가리키는 훅에서는 기록한 시작·끝 경계를 사용해 양쪽의 규약을 맞춘다. 이동이 결합됐거나 누락돼 경계가 불명확하면 가능한 시간 범위를 남긴다.
- 탭별 **시작 오차, 해제 오차**는 각각 서버 적용 경계에서 소유자 예측 경계를 뺀 부호 있는 ms다. 적용 지속시간 오차(ms), 달리기 상한으로 실제 처리한 이동 거리(cm), 입력 구간과의 겹침, 허용되지 않은 잔류 달리기 시간도 집계한다. 빠른 두 탭은 순서 보존 일대일 매칭 후 정상·누락·하나로 병합·분할·지연·해제 미관측을 구분한다. 한 서버 구간으로 두 탭을 성공 처리하지 않는다. `TapMissingInAppliedWindow`는 이전 기록과의 비교용으로 유지한다.
- 입력 후 **최소 기존 배수 구간**을 관측하고, 마지막 해제를 서버가 처리하여 걷기 이동을 관측할 때까지 진단 캡처를 연장한다. 제안 기본 상한은 해제 입력 후 10초다. 초과 시 마지막 관측 시각, 지속시간 하한, 미관측 에지를 남긴다. 완결 사례의 오차 분위수와 미완결 비율을 함께 표시한다. 연장 배수 시간과 바이트를 고정 길이 비용 구간에 합치지 않는다.
- 우선 기존 지터 200ms·손실 10%의 5.651초, 100ms·0%의 동일 서버 시각 처리, 300ms·0%의 해제 미관측 사례를 재분석한다. 단일 서버 시계에서 계산한 처리 간격, 소유자→서버 경과시간, CMC 이동 시간상 적용 간격을 나란히 출력한다. 오래된 자료로 편도 지연을 복원할 수 없으면 NA로 남긴다.

**인수 기준.** 결과 한 줄에서 누름과 해제의 양측 원본, 수락·거부, 실제 적용 구간과 거리를 찾을 수 있다. 해제가 늦게 도착한 탭, 이동 사이에서 두 에지가 모두 처리된 탭, 측정 종료까지 열린 탭이 다른 결과로 집계된다. 50ms 입력은 실제 저장 이동 길이와 표본 수를 함께 보여준다. 관찰자 화면은 서버 복제 이동·애니메이션과 메시 스무딩을 확인하는 데 사용한다.

## 3단계 · 별도 프로세스에서 전환 빈도별 손익 측정

**실행 경로.** 현재 `SprintTrialConsole.cpp`는 `WITH_EDITOR && DO_ENABLE_NET_TEST`에서 같은 프로세스의 PIE 월드 세 개를 직접 찾고, 프로파일러도 단일 추적 안에서 서버와 소유자를 찾는다. 새 PowerShell 런처 `Scripts/RunSprintCostTrial.ps1`과 시험용 역할별 실행기를 추가한다. 기존 게임·에디터 타깃을 쓰는 Development Editor 실행 파일로 전용 서버(`-server`)와 소유자·관찰자(`-game`) 세 프로세스를 같은 호스트에서 실행한다. 프로젝트에 별도 Server Target을 요구하지 않는다. 역할별 월드와 NetMode를 확인하고 공용 입력 생성·시험 캐릭터·캡처·복구 코드를 재사용한다. 기존 Sharp 런처의 프로세스·포트 관리 방식을 참고한다. [PIE 실행기](../../Source/GE_AIReplication/Measurement/SprintTrialConsole.cpp) · [추적 분석기](../../Source/GE_AIReplication/Measurement/SprintTrialProfile.cpp) · [별도 프로세스 실행 예](../../Scripts/RunSharpTrial.ps1)

- 런처가 실행 ID, 셀 ID, 역할, 경로, 포트, 맵과 입력표를 배포한다. 세 역할의 접속, 소유권·대상 복제, 워밍업, 기록 준비 완료 뒤 시작한다. 같은 호스트의 공통 단조 시계를 사용하고 시작·종료 마커로 변환 오차를 검증한다. 프로세스별 WorldSeconds나 추적 원점은 직접 빼지 않는다. 서로 다른 시계를 연결할 근거가 없으면 편도 시간만 NA로 둔다. 각 송신측 추적을 별도로 읽고 실행·역할·연결·액터·기록 구간으로 결합한다. 준비·종료 조율은 로컬 파일 또는 측정 구간 밖 제어 메시지를 사용한다.
- 지터·손실은 기존과 동일하게 **소유자 연결 한쪽**에서 송신/수신에 적용한다. 서버와 관찰자는 추가 에뮬레이션 0이다. 소유자 기본 지연 50ms, 송신 lag 범위·PktJitter, 고정 수신 지연, 양방향 loss의 **실제 적용값**을 manifest에 남긴다. 동일 난수열은 별도로 보장된 경우에만 기재한다. 시험 맵·시작 자세·카메라·경로·목표 FPS·서버 틱·실측 프레임·CMC 허용 오차와 보정 빈도 설정·빌드·추적 설정을 기록한다. 경로는 같은 평지의 반복 가능한 입력 궤적으로 정하고, 장시간 이동의 벽 충돌·낙하·리셋은 검출한다. 구간 사이 원점 복귀는 측정 밖에서 수행한다.
- **제안 기본 프로필**은 고정 60초 측정이다. ① 60초 걷기(전환 0), ② 워밍업부터 달리는 60초 유지(측정 중 전환 0), ③ 분당 2·6·12·30회 누름/해제 에지를 균등 배치한 입력이다. ③은 경계 밖 시작·종료 준비를 두고 달리기 점유율을 50%로 고정한다(한 번 누르고 떼면 2회). ④ 짧은 탭·연속 탭이 섞인 실제 사용 예시 입력표를 별도 코스로 둔다. 길이·점유율·순서를 저장해 세 방식에서 재생한다. 실제 플레이 기록이 없으면 ‘합성 입력’으로 표시한다. 빈도별 비교에는 동등한 점유율의 ③을 사용하고, ①·②는 상시 비용 대조군으로 보고한다.
- 파일럿은 지연·손실 없는 대조 조건과 기존 이상 조건 200ms/10%에서 한 블록씩 실행한다. 본 측정은 기존 9개 조건 × 세 방식, 블록마다 실행 순서를 순환한다. 제안 초기 반복은 **조건당 6개 짝 블록**이며 파일럿은 별도 집계한다. 실제 시험 전에 반복 수와 입력 품질 허용치(누락률, 해제 오차, 보정 후 변위)를 계획 파일에 고정한다. 불완전한 블록에서도 유효한 방식 쌍은 보존한다. 실패·취소·재시도는 별도 시도 ID를 남기고 같은 결과를 두 번 합산하지 않는다. 125ms 프레임 중단 등 기존 유효성 기준을 세 방식에 동일하게 적용한다.

### 비용과 채택 판정

| 지표 | 계산과 해석 |
|---|---|
| 소유자 연결 양방향 B/s | 측정 구간 소유자→서버와 서버→해당 소유자의 **각 송신측** 연결 누적 OutTotalBytes 차분을 실제 구간 초로 정규화해 합산한다. 카운터가 포함하는 헤더·재전송·에뮬레이션 처리 경계를 manifest에 적는다. 수신측 중복 합산, 관찰자 연결과 조율 트래픽의 혼입, 카운터 리셋을 확인한다. 기존 서버의 In+Out 값은 구분해 보존한다. OS 전선상 바이트가 필요하면 별도 패킷 캡처로 검증한다. |
| 이동 RPC 콘텐츠 bit/s | 기존 U+D를 재사용한다. New/Pending/Old, 상태 RPC, ACK·보정 응답, 미귀속 재전송을 표시한다. 1비트 필드 자체의 비용은 해당 구간 직렬화한 New+Pending+Old 레코드 수 ÷ 초로 계산한다. 연결 B/s와 포함 범위·단위가 다르다. |
| 플레이 품질·계산 비용 | 소유자 수신 보정/분, 보정 후 변위 p95와 표본 수, 위치 오차 p95, 재생 CPU ms/s, 입력 누락·시작/해제·지속시간 오차와 거리, 관찰자 메시 오프셋을 제시한다. 보정 0건에서는 횟수는 0이고 변위 분위수는 NA다. |
| 손익분기점 | 같은 환경·경로·입력표·빈도·블록에서 후보와 기준의 연결 B/s 차이(후보−기준)를 구한다. 주 비교는 MoveDataBit−SeparateRpc이며 MoveDataBit−MoveData도 출력한다. 블록별 짝차이의 중앙값과 블록 재표집 95% 구간을 제시한다. 입력 품질 허용치를 충족한 두 방식에서만 비용 우열을 채택 근거로 사용한다. 품질 실패 행도 전체 표에 보존한다. |

환경별로 인접 빈도에서 비용 차이 부호가 바뀌면 **관측된 전환 빈도 구간**을 보고한다. 예를 들어 6회/분과 12회/분 사이에서만 바뀌면 그 사이 빈도를 추가 측정한다. 모든 점이 절감·증가이면 관측 범위 전체의 결과를, 구간이 0을 포함하거나 여러 번 교차하면 불확실한 범위를 제시한다. 걷기 전용과 점유율 50% 자료 사이를 보간하거나 9개 네트워크 조건을 하나의 임계값으로 합치지 않는다.

## 결과 파일과 실패 처리

- 기존 `CompareSprintTrials.ps1`에 새 스키마를 추가한다. 짝 키에 프로세스 구성, 입력표 해시·패턴·빈도·점유율, 네트워크 조건, 블록, 측정 구간과 공통 환경을 포함한다. 방식과 개별 실행 ID는 짝의 구성원을 식별한다. 서로 다른 패턴의 첫 걷기 구간이 하나로 합쳐지지 않도록 한다. 기존 프로파일 명령·결과 열·구버전 비교는 계속 지원한다.
- 작업 폴더에 `README.md`를 먼저 만들고 manifest에 입력 계획, 실제 시각, 단위·시계, 스키마 버전, 역할별 추적 경로, 누락 사유, 결과 상태를 쓴다. 별도 프로세스는 역할별 폴더에 쓴다. 긴 실행의 버퍼 포화·드롭·카운터 래핑을 검출한다. 고정 버퍼는 예상 레코드로 예약하거나 구간 밖/백그라운드에서 분할 저장한다. 누락된 지표의 품질 판정을 무효로 표시한다. [Saved 결과물 규칙](../Legacy/Workflow/Saved_결과물_관리.md)
- `move_timeline.csv`는 이동별 예측·서버 적용·검사 연결, `correction_episodes.csv`는 보정별 근거와 원본 행 키, `input_windows.csv`는 에지별 전송·적용·타임아웃, `cost_pairs.csv`는 블록별 품질·비용 짝차이, `break_even.csv`는 빈도별 표본 수·구간·판정, `results.md`는 세 질문에 대한 결론과 미확인 항목을 담는다. 진단 단계만 실행해도 그 단계의 표를 생성한다. 기존 비용 CSV와 단위·방향·합계를 대조할 수 있어야 한다.
- 역할 단절·추적 파일 미종료·프레임 중단·취소는 셀과 역할을 명시해 종료한다. PIE에서는 원래 소유권·카메라·지연을 복구한다. 별도 프로세스에서는 해당 실행이 띄운 PID만 정리하고 부분 기록은 보존한다. 종료되지 않은 추적은 재분석 대기로 표시한다. 재분석은 새 작업 폴더를 생성하며 기존 원본을 보존한다.

## 구현 완료 후 사용자가 확인할 순서

아래는 Development Editor 빌드의 수동 확인 순서다. PowerShell 명령은 프로젝트 루트의 PowerShell 7에서 실행한다. 별도 프로세스 실험은 기본 UDP 포트 18777을 사용하며 `-Port`로 변경할 수 있다. `TapSweep`은 방식당 36개 시행이고, 기본 파일럿은 18개 실행이다. 6블록 `FrequencyMatrix`는 총 1,134개 실행이므로 고정 측정 구간만 약 18.9시간이다. 맵 로드·배수·분석 시간이 별도로 든다.

서버가 위치 보정 응답을 큐에 넣은 행은 `ServerResponseQueued`에 있다. `rpc_bits.csv`는 NetTrace에서 확인한 송신 범위다. `rpc_attempts.csv`의 `PacketHint`는 패킷 번호가 맞는 송신 후보를 뜻한다. Reliable bunch 순번을 확인할 수 없는 재전송은 귀속을 보류하며 송신·수신 일치 건수로 해석하지 않는다. `break_even.csv`의 주 비용은 엔진 연결 카운터의 양방향 송신 차분이다. 패킷 헤더 추정치와 시뮬레이션에서 드롭된 송신을 포함하므로 OS에서 캡처한 실측 바이트와 범위가 다를 수 있다.

1. **기존 Tap 재분석.** Development Editor 콘솔에서 다음 명령을 입력한다. 완료 메시지의 새 작업 폴더에서 200ms/10% 셀의 5.651초를 확인하고, 해제를 관측하지 못한 다른 셀에 미확인 사유가 남는지 확인한다.

   ```text
   SprintTrial.Run ProfileReport 20261123-153304-SprintMatrix-SeparateRpc-88658999
   ```

2. **세 방식의 짧은 입력 비교.** 같은 맵에서 Play As Client, 2 Players, Run Under One Process로 시작한다. 평지에 정지한 같은 소유자 창의 콘솔에서 한 줄씩 입력한다. 직전 배치 완료와 원래 캐릭터 복귀 후 다음 줄을 실행한다. 서버의 실제 적용 구간, 소유자의 누름·해제와 보정, 관찰자의 메시 이동을 확인한다. 취소는 `SprintTrial.Close`다.

   ```text
   SprintTrial.SeparateRpc 1 Profile TapSweep
   SprintTrial.MoveData 1 Profile TapSweep
   SprintTrial.MoveDataBit 1 Profile TapSweep
   ```

3. **별도 프로세스 파일럿.** PIE 종료 후 프로젝트 루트 PowerShell에서 첫 줄로 맵·역할·포트·입력표·출력 경로를 확인하고, 두 번째 줄로 실행한다. 런처는 전체 배치 완료와 결과 경로를 표시한다.

   ```powershell
   ./Scripts/RunSprintCostTrial.ps1 -Plan Pilot -Blocks 1 -DryRun
   ./Scripts/RunSprintCostTrial.ps1 -Plan Pilot -Blocks 1
   ```

4. **반복 후 판정.** 파일럿에서 셋의 시작 자세·프로필, 연결 방향별 바이트와 CMC 이동 조인, Tap 해제·배수 경계가 맞는지 확인한다. 파일럿이 출력한 `quality_policy.json` 양식의 `MaxMissedTapPct`, `MaxAbsReleaseErrorP95Ms`, `MaxReconciliationP95Cm`에 팀의 허용치를 기입한다. 런처에 경로를 주면 본 측정 manifest에 복사하고 결과 비교에 적용한다. 허용치가 비어 있으면 측정·짝차이 산출은 진행하고 채택 판정을 보류한다. 아래 경로는 실제 파일럿 폴더로 바꾼다. 런처는 기존 비교 스크립트에 완료된 입력을 넘기고 `results.md`와 `break_even.csv` 경로를 출력한다. 서버와 소유자의 수치, 관찰자 품질, 실패·미정 셀을 함께 검토한다.

   ```powershell
   ./Scripts/RunSprintCostTrial.ps1 -Plan FrequencyMatrix -Blocks 6 -QualityPolicy 'Saved/Tasks/<파일럿 폴더>/quality_policy.json'
   ```

구현 담당자는 변경 후 `GE_AIReplicationEditor Win64 Development` 빌드 결과와 실제 지원되는 명령 순서를 전달한다. 자동화·PIE·별도 프로세스 실험은 사용자가 직접 수행하거나 별도로 실행을 요청할 때 진행한다.
