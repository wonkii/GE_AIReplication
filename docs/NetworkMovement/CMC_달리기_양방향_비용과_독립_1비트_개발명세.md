# 달리기 상태 전송과 보정 절약분의 양방향 비용 비교

UE 5.8.3 전용 서버와 소유자 사이에서 **같은 달리기를 제공할 때, 클라이언트가 추가로 보낸 이동 비트를 서버가 절약한 이동 응답 비트로 회수하는가**를 측정한다. 첫 산출물은 기존 추적 두 개로 계산한 양방향 손익표다. 다음 산출물은 새 기록에서 증가 원인을 설명하는 표이며, 과거 이동 동봉이 주요 비용으로 확인되면 독립 1비트 방식까지 비교한다. 기존 시험의 환경·역할·계측 단위는 [걷기와 달리기 프로파일링 명세](CMC_걷기와_달리기_프로파일링_개발명세.md)를 따른다.

## 출발점과 판정식

2026-11-23 블록 1의 SeparateRpc와 MoveData는 같은 시작 자세로 각각 9셀을 완료했다. MoveData의 이동·상태 RPC 콘텐츠는 총 87,563비트 더 많았고 소유자가 받은 보정은 181회에서 97회로 줄었다. 두 기록의 길이가 비슷하다고 보고 계산한 손익분기점은 줄어든 보정당 약 130 B다. 보정 한 번의 실제 크기는 다음 단계에서 측정한다. 기본 걷기는 달리기 기능이 없는 참고군이며 시작 방향도 약 4° 달랐다.

| 같은 셀·구간의 측정값 | 정의 |
|---|---|
| U | 소유자 송신 이동 RPC와 달리기 상태 RPC의 콘텐츠 비트 합계 ÷ 실제 구간 초 |
| D | 서버가 그 소유자에게 보낸 CMC 이동 응답 RPC의 콘텐츠 비트 합계 ÷ 실제 구간 초. 정상 ACK, 위치 보정, 종류 미확인 응답을 포함한다. |
| 순증가량 | 후보의 (U + D)에서 SeparateRpc의 (U + D)를 뺀 값. 음수이면 측정 대상 RPC에서 대역폭을 절약했다. |
| 품질 | 소유자의 수신 보정 횟수와 분당 횟수, 실제 보정·재생 전후 변위 p95, 같은 이동의 위치 오차 p95, 전환 후 100 ms 오차 p95와 대응 표본 수 |

구간 전체와 셀 전체의 **송신 기준·압축 전 RPC 콘텐츠**를 같은 경계에서 비교한다. 전달 실패한 최초 송신도 기록한다. 함수에 귀속할 수 있는 재전송은 한 번만 세고, 미귀속 재전송은 방향별 별도 열로 둔다. 미귀속분을 각 후보에 가장 유리하거나 불리하게 귀속한 범위에서 순증가량의 부호가 바뀌면 절감 판정을 보류한다. 실제 연결의 양방향 B/s, 소유자 재생 CPU, 관찰자 메시 오프셋은 별도 지표다. 보정을 정상 ACK로 대체한 경우 양쪽 응답 크기의 차이가 손익에 반영된다.

## 1단계 · 보관 중인 추적에서 손익 계산

- `SprintTrialProfile.cpp`의 `CollectTraffic`과 `AnalyzeBatch`를 확장한다. 기존 phase 북마크를 사용해 소유자 송신 `ServerMovePacked`·`ServerRequestSprint`와 **서버 송신** `ClientMoveResponsePacked`를 읽는다. 인스턴스·연결·시험 캐릭터 NetId와 함수 범위를 확인한다. 같은 패킷의 수신 사본과 중첩 이벤트를 합산하지 않는다.
- 기존 manifest에는 소유자 측 연결 식별자가 있다. 서버 측 식별자는 해당 서버 인스턴스에서 시험 캐릭터에 대한 응답을 보내는 연결과 추적의 연결 메타데이터로 확인한다. 양 끝의 연결 번호가 같다고 가정하지 않는다. 모호하면 D를 `NA`로 기록한다. 새 manifest에는 서버 인스턴스·소유자 연결·양 끝의 캐릭터 식별자를 명시한다.
- 기존 추적에서 응답 RPC 경계만 식별돼도 D와 순증가량은 산출한다. ACK·보정 세부 분류나 OldMove 정보가 없는 셀은 해당 열만 `NA`로 둔다. 완전한 수집에서 실제 호출이 0인 경우와 구별한다.
- `SprintTrial.Run ProfileReport <배치폴더명>`을 재사용한다. 읽기 전용 원본은 `.utrace`, manifest, 역할별 CSV이며, 새 분석 결과는 스키마 버전과 원본 배치 ID를 포함한 별도 작업 폴더에 쓴다. README를 먼저 만들고 마지막에 사용자에게 비교 입력 경로를 출력한다. 기존 보고서와 재분석 결과를 독립적으로 재현할 수 있어야 한다.

## 2단계 · 새 기록에서 증가 원인 확인

| 관측 위치 | 남길 자료와 확인할 질문 |
|---|---|
| 소유자 이동 직렬화 | `CallServerMovePacked`의 New/Pending/Old 입력과 실제 직렬화 경계를 연결한다. 이동별 epoch·timestamp, 달리기 의도, 압축 플래그, 마지막 ACK 플래그, 각 이동의 기록 시작·끝 비트와 RPC 전체 비트를 남긴다. OldMove가 들어간 횟수와 해당 샘플에서 OldMove가 차지한 비트로 송신 증가분을 얼마나 설명하는가? |
| 서버 응답 직렬화 | 공용 `FCharacterMoveResponseDataContainer`의 `ServerFillResponseData`·직렬화 경로에서 `bAckGoodMove`, 대상 이동 timestamp, 응답 종류, 직렬화 비트를 남긴다. 서버의 위치 오차 검사, 응답 작성, 실제 송신, 소유자 수신을 각각 집계한다. |
| 송신 범위 대응 | TrialId·방향·액터·연결·엔진 프레임·호출 순번과 추적상 패킷/콘텐츠 범위를 사용한다. 같은 프레임 다중 호출과 패킷 병합을 허용한다. 유일하게 대응한 이벤트만 세부 분류하고, 미대응·중복·실제 송신되지 않은 작성 건수를 함께 기록한다. 응답 총비트는 콘텐츠 범위에서 직접 구한다. |

시험 전용 컴포넌트에서 UE 5.8의 가상 함수와 수명이 보장된 이동·응답 컨테이너를 사용한다. 공용 계측은 기존 직렬화 결과를 보존하고 진단 필드는 로컬 버퍼나 trace에만 쓴다. 세 방식에 같은 계측을 적용한다. New/Pending/Old 내부 비트, RPC 경계의 나머지 비트를 구분하여 합계가 맞는지 확인한다. 444–460비트인 호출을 길이만으로 OldMove로 분류하지 않는다. 같은 입력·조건의 반복에서 OldMove 증가분이 가장 큰 설명 항목인지 확인하고 나서 3단계 후보를 평가한다.

## 3단계 · 독립 1비트 후보

- 시험용 이름은 `MoveDataBit`이다. `FCharacterNetworkMoveData`를 확장해 기본 직렬화 뒤에 **해당 저장 이동 시점의** `bWantsSprint`를 `SerializeBits(..., 1)`로 읽고 쓴다. 지속 컨테이너의 New/Pending/Old 세 슬롯 모두 같은 형식을 사용한다. 오류와 재사용 시 초기화도 처리한다. 양 끝에서 한 시험 캐릭터 클래스가 같은 형식을 사용한다.
- `FSprintSavedMove`의 의도 저장, 전환 경계 결합 금지, `PrepMoveFor` 재생, 재생 후 현재 입력 복원은 기존 MoveData와 공유한다. 후보는 달리기 의도를 독립 필드에만 싣는다. 엔진의 점프·앉기·이동 모드 중요도와 과거 이동 선택은 기본 동작을 따른다.
- 서버는 **실제로 처리하는 이동 각각의** 독립 비트를 읽어 이동 물리 전에 기존 달리기 정책을 적용한다. 기존 `UpdateFromCompressedFlags`가 후보의 의도를 다시 덮어쓰지 않게 한다. 접지·앉기 등 서버 자격 검사가 최종 속도를 결정한다. 소유자는 즉시 예측하고 관찰자는 서버 복제와 기존 스무딩을 사용한다.
- 짧은 탭의 press/release가 모두 손실되면 이후 걷기 비트만으로 서버가 그 탭을 복원할 수 없다. 소유자 입력 횟수, 서버에서 실제 재현한 달리기 구간 수·거리, 누락된 탭 수와 소유자 보정 거리를 필수 품질 결과로 둔다.

## 실험 조건과 결과물

- 기존 9개 지터·손실 조건, 350/650 cm/s, 워밍업·정지·배수, 125 ms 중단·복구 절차를 재사용한다. 세 달리기 구현이 같은 맵·위치·방향·프레임 조건·입력 패턴을 사용하도록 하고, 시작 자세 불일치는 비교에서 표시한다.
- 입력은 첫 2초 걷기 뒤 `Toggle`은 기존 2초 동안 250 ms마다 전환, `Hold`는 2초 시점부터 4초 시점까지 유지 후 해제, `Tap`은 2초 시점부터 100 ms 동안 한 번 누른 뒤 해제한다. 전방 입력은 6초까지, 정지는 8초까지, 이후 1초는 늦은 응답을 수집한다. 실제 press/release 타임스탬프를 기록하고 Hold 해제 직후의 오차도 집계한다.
- `SprintTrialConsole.cpp`의 기존 행렬 파서에 선택형 패턴을 추가한다. `Profile` 뒤 패턴 생략 시 기존 Toggle이다. `MoveDataBit`만 시험용 방식 하나를 추가한다. `CompareSprintTrials.ps1`은 같은 패턴·환경·블록·셀에서 SeparateRpc 대비 두 후보, 기존 MoveData 대비 독립 비트 후보의 짝차이를 계산한다. 구버전의 두 방식 비교도 지원한다.
- `rpc_bits.csv` 확장 결과에는 방향·RPC·응답 종류·비트 범위·대응 상태를, `profile.csv` 확장 결과에는 U·D, ACK/보정/미분류 비트, Old/Pending 동봉 빈도와 비트, 재전송, CPU·품질·표본 수를 둔다. 비교표에 원값·짝차이·유효 블록 수·실패 사유를 기록한다. 같은 블록에서 한 방식이 누락돼도 성립하는 나머지 쌍은 보존한다.
- 채택은 반복 블록에서 양방향 콘텐츠 순증가량이 음수이고, 기존 MoveData 대비 보정 거리·전환 오차·탭 누락이 프로젝트 허용 범위 안일 때 검토한다. 허용 한계는 측정 전에 팀이 정한다. 첫 블록에서는 관측값과 손익분기점만 보고하고, 반복 블록마다 실행 순서를 순환한다. 손실률이 높은 셀과 원격 관찰자 품질을 별도로 표시한다.

## 구현 후 사용자가 직접 확인할 순서

아래는 다음 구현의 명령 계약이다. 구현 담당자는 에디터 빌드 결과와 실제 지원되는 명령 순서를 사용자에게 전달한다.

1. **기존 기록 재분석.** 새 Development Editor의 콘솔에서 다음 두 명령을 차례로 실행한다. 각 명령이 끝나면 출력한 분석 폴더를 기록한다. 9개 조건의 서버 응답 총비트와 대응 상태가 생성되는지 확인한다.

   ```text
   SprintTrial.Run ProfileReport 20261123-130849-SprintMatrix-SeparateRpc-71C3A8E7
   SprintTrial.Run ProfileReport 20261123-131037-SprintMatrix-MoveData-E04435B8
   ```

2. **전환 비용 측정.** PIE를 Play As Client, 2 Players, Run Under One Process로 시작한다. 같은 소유자 창에서 평지에 정지하고 카메라 방향을 고정한다. 각 배치의 프로파일 완료 메시지 뒤에 다음 줄을 입력한다. 먼저 두 기존 방식에서 서버 ACK·보정 분류와 OldMove 증가분을 확인한다. 독립 비트 후보 구현 후 세 번째 명령으로 같은 블록을 채운다.

   ```text
   SprintTrial.SeparateRpc 1 Profile Toggle
   SprintTrial.MoveData 1 Profile Toggle
   SprintTrial.MoveDataBit 1 Profile Toggle
   ```

3. **유지와 짧은 탭 확인.** 같은 소유자 콘솔에서 한 줄씩 실행한다. 소유자에서는 Shift 의도에 따른 가속과 보정 변위, 서버에서는 실제 달리기 재현 여부와 응답 비트, 원격 창에서는 이동·애니메이션과 메시 오프셋을 확인한다.

   ```text
   SprintTrial.SeparateRpc 1 Profile Hold
   SprintTrial.MoveData 1 Profile Hold
   SprintTrial.MoveDataBit 1 Profile Hold
   SprintTrial.SeparateRpc 1 Profile Tap
   SprintTrial.MoveData 1 Profile Tap
   SprintTrial.MoveDataBit 1 Profile Tap
   ```

4. **결과 비교.** 프로젝트 루트 PowerShell에서 아래 경로를 같은 패턴의 실제 출력 폴더로 바꾸어 실행한다. 구버전 재분석은 두 폴더, 후보 포함 실험은 세 폴더를 전달한다. 출력된 비교 폴더에서 셀별 U·D 짝차이와 품질을 확인한다. 반복 시 세 방식에 같은 새 블록 번호를 준다. 진행 중인 PIE 배치를 취소할 때는 소유자 콘솔에 `SprintTrial.Close`를 입력한다.

   ```powershell
   ./Scripts/CompareSprintTrials.ps1 -RunFolders @(
       'Saved/Tasks/<SeparateRpc 결과 폴더>',
       'Saved/Tasks/<MoveData 결과 폴더>',
       'Saved/Tasks/<MoveDataBit 결과 폴더>'
   )
   ```
