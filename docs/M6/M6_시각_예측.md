# M6. 사건 기반 클라이언트 시각 예측

> 상태: 개발 예정. [전체 아키텍처](../Architecture/Unreal_Sharp_Movement_마일스톤_구현계획.md) · 선행: [M5](../M5/M5_전송_정책.md) · 다음: [M7](../M7/M7_견고성.md)

첫 Snapshot 수신 이후의 Mesh만 조절한다. Capsule 권한과 기본 이동 복제는 유지한다.

## 담당 파일과 폴더

아래 경로는 저장소 루트 기준이다. 파일이 기존 단계에서 생성되었다면 이 단계에서는 확장한다.

| 경로 | 역할 |
|---|---|
| `Source/GE_AIReplication/SharpMovement/Prediction/SharpVisualPredictorComponent.h/.cpp` | Simulated Proxy Mesh의 단기 예측·수렴 |
| `Source/GE_AIReplication/SharpMovement/Enemy/SharpEnemyCharacter.h/.cpp` | OnRep Snapshot 검증과 Predictor 연결 |

## 개발 및 검증 사항

**목표:** 첫 Snapshot을 받은 뒤 다음 기본 이동 상태까지의 Mesh 경로를 개선한다.

**구현 작업**

1. `OnRep_SharpMoveSnapshot`에서는 Snapshot을 보관하고 `SequenceId`·시각의 유효성만 검사한다. **즉시 Capsule을 SetActorLocation 하지 않는다.** 실제 표시 위치 계산은 클라이언트 Tick에서 한다.
2. `age = GetServerWorldTimeSeconds() - Snapshot.ServerTime`으로 사건 후 경과 시간을 구한다. 너무 늦게 도착했거나 이미 새 서버 상태가 적용된 사건은 버린다.
3. 첫 모델은 장애물 없는 장면의 짧은 등속 예측 `p = p0 + v_post × age`다. 낙하 모델은 검증된 조건에서만 중력 항을 추가한다. Walking의 마찰·AI 경로 추종·충돌을 단순 등속 모델이 재현한다고 가정하지 않는다.
4. 클라이언트 Simulated Proxy에서 CMC의 `NetworkSmoothingMode`와 프로젝트의 Mesh 보정이 **중복 적용되지 않도록** 구성한다. 첫 시제품은 제안 모드에서 내장 smoothing을 끄고 Mesh의 시각적 offset만 로컬로 계산한다. 이때 CMC가 Mesh 상대 위치를 다시 쓰는지 확인한다. 간섭이 있으면 C++ CMC subclass의 smoothing 훅을 사용한다.
5. `MaxPredictionHorizon`, `MaxVisualOffset`, 시각적 수렴 시간은 설정값으로 둔다. 다음 서버 상태·착지·충돌·Movement Mode 변화·시간 초과 시 예측을 종료하고 Mesh를 복제된 Capsule 경로로 수렴시킨다.
6. `EventOnly + 동일 시각 보정(예측 없음)` 대조군을 두어 **시각 보정 알고리즘 변경**과 **궤적 예측**의 효과를 분리한다.

**산출물:** 클라이언트 시각 예측 시연 및 오류 로그. 기본 CMC·EventOnly·EventPredictor의 같은 장면 영상.

**완료 기준:** 캡슐 권한을 바꾸지 않고, 첫 수신 이후 Mesh 오차 또는 보정 거리의 개선 여부를 측정할 수 있다. 큰 Impulse라고 예측 시간을 무조건 늘리지 않는다.
