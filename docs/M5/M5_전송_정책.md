# M5. 사건 직후 전송 방식 비교

> 상태: 개발 예정. [전체 아키텍처](../Architecture/Unreal_Sharp_Movement_마일스톤_구현계획.md) · 선행: [M4](../M4/M4_Detector.md) · 다음: [M6](../M6/M6_시각_예측.md)

## 개발 및 검증 사항

**목표:** 클라이언트 예측기를 만들기 전에, 어떤 전송 방식이 실제로 필요한지 분리한다.

**구현 작업**

1. `SingleShot`: Detector가 사건을 감지한 뒤 Enemy에 `ForceNetUpdate()` 한 번 요청한다.
2. `Burst`: 감지 뒤 짧은 시간만 Enemy의 `NetUpdateFrequency`를 높이고 원래 값으로 복구한다.
3. `EventOnly`: Snapshot Struct를 갱신하고 `ForceNetUpdate()`를 요청하되, 클라이언트의 표시 방식은 기본 CMC 그대로 둔다. 이를 통해 Snapshot의 **전송 오버헤드**를 분리한다.
4. `Adaptive` 및 `AlwaysHigh`를 같은 장면에서 기준선으로 실행한다.
5. 실제 전송 여부·수신 시각·비용을 측정한다. `ForceNetUpdate`는 요청이지 RTT·relevancy·대역폭 제한을 없애는 기능이 아니다.

**산출물:** 첫 새 상태 도착 시간과 위치 오차 대비 bytes/s 그래프.

**완료 기준:** `SingleShot`과 `Burst` 중 어느 방식이 개선을 만드는지, Snapshot이 기본 이동 상태보다 먼저 도착하는지 **측정값으로** 판단한다.
