# Game Animation Sample 기반 환경 제약 Motion Warping 연구 실행 계획

작성일 2026-11-03 KST. 대상 저장소는 GE_AIReplication, 엔진 기준은 프로젝트에 지정된 UE 5.8이다. 아래 완료 조건은 앞으로 검증할 항목이다.

## 연구 범위와 진행 순서

**정적 벽 근처에서 같은 피격 Montage를 실행할 때, 안전 목표를 사용하는 Motion Warping이 기본 CMC 실행보다 충돌 후 이동과 표시를 안정화하면서 의도한 후퇴를 유지하는지 검증한다.** 현재 전투에서 재현 가능한 서버 Enemy 피격부터 시작한다. 환경에 따른 동작 선택과 시간별 QP 보정은 각각 효과를 분리해서 추가한다. 움직이는 상대를 향한 공격과 네트워크 행동 계획 공유는 별도 확장 실험으로 둔다. 이 순서는 현재 통합된 전투 경로에서 가장 적은 변경으로 첫 기준선을 확보하기 위한 제안이다.

Game Animation Sample은 이동·트래버설 자산과 AnimBP의 Chooser → Pose Search → Montage Slot 연결을 참고할 출발점이다. 피격이나 공격에 적합한 원본 자산은 실제 Root Track과 자세를 검사해 결정한다. 샘플의 Orientation Warping, Offset Root Bone, Montage Motion Warping은 각각 실험에 미치는 영향이 다르므로 설정을 분리해서 기록한다. [Epic Game Animation Sample](https://dev.epicgames.com/documentation/unreal-engine/game-animation-sample-project-in-unreal-engine)

| 순서 | 작업 단위 | 결과물 | 진입 조건 |
|---|---|---|---|
| 01–02 | 샘플 확인과 자산 선정 | 버전·자산 목록, Root Track 검사 결과 | 샘플 확보 |
| 03–04 | 실험 맵과 반복 가능한 기준선 | 맵, 실행기, 원본 로그와 기준선 표 | 피격 자산 1개 선정 |

| 06 | 환경에 따른 동작 선택 | 후보 라이브러리와 선택 근거 | 대체 후보 1개 이상 확보 |
| 07–08 | QP 필요성 판단과 UE 적용 | 수치 프로토타입, 비교 결과 | 단순 보정에서 재현되는 품질 문제 확인 |

각 번호를 독립 작업 요청으로 맡길 수 있다. 03 이후는 아래 체크 항목 중 **구현 → 실행 → 결과 검토**를 필요에 따라 별도 작업으로 나눈다. 완료 시 수정 파일, 실행 명령, 통과 여부, 다음 단계 입력을 기록한다.

## 01. 샘플 버전과 실행 환경 고정

- [ ] **로컬 조사.** 설치 엔진 빌드, 프로젝트 엔진 연결, 기존 GASP 폴더와 자산 감사 결과를 확인한다. 새 샘플이 필요하면 Epic Games Launcher의 Library에서 Game Animation Sample을 별도 프로젝트로 생성한다. Launcher 로그인·다운로드나 실제 에디터 화면 확인이 필요한 구간은 팀원이 수행하거나 화면을 사용할 수 있는 환경에서 진행한다.
- [ ] **독립 실행 확인.** 샘플 맵에서 걷기·정지·회전·트래버설을 확인하고, 샘플 버전과 활성 플러그인, 실제 사용 중인 AnimBP·Chooser·Pose Search DB 경로를 기록한다. 문서상의 자산명과 설치본이 다르면 설치본을 기준으로 적는다.
- [ ] **역할 분리.** 샘플 프로젝트는 비교용으로 보관한다. 연구 실험은 GE_AIReplication 안의 독립 맵에서 수행하고, 전투·CMC·Recorder는 저장소의 기존 경로를 재사용한다.

**완료 기준.** 같은 엔진으로 두 프로젝트가 열리고 샘플 대표 동작이 재생된다. 버전과 자산 경로를 다음 작업이 재현할 수 있다.

## 02. Root Motion 자산 후보 감사와 최소 이관

- [ ] **후보 목록 작성.** 샘플의 정지·피벗·트래버설과 기존 피격 자산을 조사한다. 자산 경로, Skeleton, 길이, XY 누적 이동, 최대 Z, Yaw 변화, 접지 구간, 사용 가능 범위를 표로 남긴다. GASP의 이동 자산을 피격으로 쓰려면 피격 방향과 자세가 의미상 맞는지도 확인한다.
- [ ] **첫 자산 선정.** 첫 기준선에는 기존 전투에서 사용할 수 있는 긴 피격 후보 1개를 우선한다. 샘플은 자산·AnimBP 참고와 대체 후보 발굴에 활용한다. 적합한 짧은 피격 후보가 없으면 별도 제작·확보를 06의 선행 작업으로 남긴다.
- [ ] **이관과 재검사.** 필요한 Sequence만 Content Browser의 Migrate로 가져오고 Asset Report에서 의존성과 경로 충돌을 확인한다. Skeleton이 다르면 IK Retargeter를 검토한다. 이관 후 Root Track, Root Lock, Montage Slot, 추출 설정과 실제 Capsule 이동을 다시 잰다. Sequence 원본과 실험용 Montage를 구분한다.

**완료 기준.** 첫 Montage가 목표 Skeleton에서 재생되며, 무장애 실행에서 의도한 방향으로 Capsule이 이동한다. 원본·이관·리타게팅 후의 측정값이 남아 있다. [Epic 샘플 자산 이관 안내](https://dev.epicgames.com/documentation/unreal-engine/game-animation-sample-project-in-unreal-engine#exportinganimations)

## 03. 최소 실험 맵과 피격 실행 경로

- [ ] **맵 구성.** 평지, Player, Enemy 한 명, 제거하거나 위치를 바꿀 수 있는 수직 벽, 고정 카메라를 배치한다. 벽 거리의 기준은 Capsule 표면과 벽 표면 사이 여유로 통일한다.
- [ ] **고정 1타 실행.** 기존 공격 Notify·서버 명중·HitReactionComponent 경로에서 공격과 피격이 각각 한 번만 발생하도록 실험 진입점을 만든다. 동일한 Montage Section, 재생 속도, 시작 자세, Capsule 크기를 고정한다. Spline·Impulse·별도 Mesh 예측의 실험 개입 여부를 기록한다.
- [ ] **실행 검증.** 무장애와 벽 조건에서 시작 위치, Capsule 경로, 실제 접촉, 종료 상태를 확인한다. 움직임을 덮는 AnimBP 레이어가 있다면 설정을 명시하고 군별로 동일하게 유지한다.

**완료 기준.** 동일 조건을 세 번 재생해 매번 피격 1회와 정상 종료를 확인한다. 벽 조건에서는 실제 접촉이 로그에 남는다. [기존 전투 실행 안내](../RootMotion_피격_벽충돌_기준선/04_공격피격_실행.md)

## 04. 기준선 계측과 반복 실행

- [ ] **기록 계약 구현.** Trial·Reaction ID, 역할, 서버 시각과 프레임을 공통 키로 정한다. 명중, Montage 시작·끝, 접촉, 리셋을 사건으로 기록한다. 원본 Root Motion 요청, 적용된 Capsule 변위, 표시 Mesh 위치를 구분한다. Proxy 보정 훅에서는 CMC의 기존 호출을 유지한다.
- [ ] **실행 자동화.** 준비 → 시작 → 명중 → 피격 종료 → 관찰 tail → 기록 저장 → 리셋의 상태를 구분한다. 초기 overlap, 실행 실패, 기록 누락에는 별도 사유를 붙인다. 저장 폴더는 실행마다 생성한다.
- [ ] **Pilot.** 먼저 무장애 실측 후퇴 거리 L을 재고, 벽 없음·여유 충분·중간 접촉·가까운 벽을 나눈다. 각 조건 3회로 재현성을 확인한 뒤 본 실험 반복 수를 정한다. 벽 접촉이 없는 여유 조건도 대조군으로 보존한다.

**완료 기준.** 하나의 Trial을 원본과 영상에서 대조할 수 있다. Capsule 관통·상승, 후퇴 거리, 화면 튐을 각각 계산하고, 연결이 있는 실행에서는 위치 오차와 보정 이벤트도 구분한다. [기존 측정 계약](../RootMotion_피격_벽충돌_기준선/03_측정과완료기준.md)

## 05. 안전 목표를 사용하는 Skew Warp

- [ ] **엔진 기준군 연결.** Motion Warping 플러그인, MotionWarpingComponent, Montage Warp Window를 실험 경로에 연결한다. 목표는 재생 전에 설정하고, 목표 없는 실행·무장애 목표·벽 앞 목표를 각각 검증한다. 기존 CMC의 이동과 충돌 처리를 사용한다.
- [ ] **안전 목표 계산.** 원본 Root Track의 시간별 구간을 실제 크기의 Capsule로 sweep한다. 첫 차단 지점의 Capsule 중심에서 여유 거리를 두고 목표를 정한다. 허용 범위보다 많이 압축해야 하거나 워핑 후 경로 검사를 통과하지 못하면 실패 사유와 fallback을 기록한다.
- [ ] **같은 자산 비교.** 고정 Montage의 기본 실행과 안전 목표 Skew Warp를 동일 맵·시작점·공격 조건으로 실행한다. 접촉·상승뿐 아니라 후퇴량, 반응 지연, 발 미끄러짐을 비교한다.

**완료 기준.** 무장애에서는 원래 이동에 근접하고, 가까운 벽에서는 목표와 실제 이동을 추적할 수 있다. 실행 불가능한 목표의 처리 결과를 재현할 수 있다. [Epic Motion Warping](https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-warping-in-unreal-engine)

## 06. 환경별 후보 선택

- [ ] **소규모 후보 라이브러리.** Long/Short 등 의미가 분명한 두 후보부터 시작한다. 후보마다 Root Track, 피격 방향, 허용 이동 범위, 접지 구간, 안전 검사 결과를 갖는다.
- [ ] **하드 제약과 점수 분리.** 초기 겹침, 금지 이동, 실행 불가능한 경로로 후보를 먼저 걸러낸다. 남은 후보는 목표 후퇴량과의 차이, Warp 변형량, 자세 전환 비용, 장애물 여유로 평가한다. 동점 규칙과 fallback을 고정한다.
- [ ] **후보 선택 효과만 비교.** 같은 안전 목표 계산기를 사용해 고정 후보와 환경별 후보 선택을 비교한다. 후보 ID, 점수 항목, 탈락 사유, 실제 후퇴량을 기록한다. 샘플의 Chooser는 후보군 분류를 넓힐 때 참고하고, 작은 후보군의 실험에서는 직접 점수화를 재현 가능하게 유지한다.

**완료 기준.** 시작 거리만 바꾸면 선택 이유와 실행 결과를 설명할 수 있다. 전부 제자리 반응을 선택했을 때 생기는 후퇴 품질 손실도 지표에 드러난다. [Environment-aware Motion Matching 논문](https://arxiv.org/abs/2510.22632), [공식 구현](https://github.com/UPC-ViRVIG/Environment-aware-Motion-Matching)

## 07. QP를 쓰기 전 수치 프로토타입

- [ ] **비교 기준 고정.** Skew Warp의 목표 제한·평활화로 남는 문제를 확인한다. 예를 들어 목표는 안전하지만 Warp 후반에 보정량이 집중되는 구간을 찾는다. 문제가 재현되면 해당 구간의 원본·목표·실제 Root Track을 내보낸다.
- [ ] **변수와 제약 설정.** 첫 모형은 평지 XY와 고정 Yaw에서 시간 구간별 추가 보정 속도 u를 구한다. 다음 위치는 현재 위치에 원본 Root 변위와 Δt × u를 더한다. 비용은 종점 오차, 추가 보정량, 연속 구간의 보정 속도 차이로 구성한다. 속도·변화율·누적 보정 한도를 선형 제약으로 둔다. 직선 벽의 안전 반평면을 모델링할 수 있는 조건에서는 제약으로 추가하고, 실제 충돌은 별도 sweep으로 확인한다.
- [ ] **독립 풀이 및 검증.** Python OSQP로 목표가 가까운 경우, 한도 밖인 경우, 원본 궤적이 충분한 경우, 모순 제약인 경우를 재생한다. 원본 대비 변형량과 제약 위반량, 해 상태, 계산 시간을 기록한다.

**완료 기준.** 같은 입력에서 제한·평활화 기준군과 QP의 결과를 재현할 수 있다. QP의 추가 이득이나 한계를 수치로 설명할 수 있어야 08을 진행한다. [OSQP 공식 MPC 예제](https://osqp.org/docs/examples/mpc.html)

## 08. UE 적용과 동적 타깃 확장

- [ ] **한 번 계획하고 적용.** 우선 공격·피격 시작 시 계획을 한 번 풀어 Warp Window의 구간별 Root Motion에 적용한다. 샘플 간 Δt, 로컬↔월드 좌표, Montage 시간↔시뮬레이션 시간 변환을 검사한다. 적용 전후 Root Motion과 CMC 실제 변위를 별도 기록한다.
- [ ] **실행 중 예외 처리.** 접촉, 도달 불가능, 시간 초과에 대한 fallback을 먼저 정의한다. 재계획은 목표가 실제로 달라지는 시나리오에서 추가하고, 계획 갱신 주기와 타격 직전 커밋 시점을 고정한다.
- [ ] **움직이는 상대 실험.** 실제 전진 Root Track과 타격 Notify가 있는 공격 자산을 확보한 뒤 별도 맵에서 시작한다. 정지·등속·반전 궤적을 재현하고, 현재 위치 목표 / 예측 목표 / 같은 예측과 같은 한도의 QP를 비교한다. Root 목표와 서버 무기 명중을 따로 기록한다.

**완료 기준.** 동일한 원본·목표·상한에서 기준군과 QP의 접지, 명중/피격 품질, 계산 시간을 비교할 수 있다. 동적 타깃 실험은 피격·벽 실험과 식별자 및 결과표를 분리한다.

## 09. 네트워크 검증과 기존 연구 연결

- [ ] **관찰 Proxy 기준선.** Dedicated Server와 관찰 Client에서 같은 피격이 재생되는지 확인한다. 인위적 지연 없음과 기존 N2 조건을 적용한다. FPS, 실제 수신 간격, 연결 bytes/s를 기록하고, 서버 충돌·Capsule 위치 오차·Mesh 표시·SmoothCorrection을 따로 집계한다.
- [ ] **계획 공유 효과 검증.** 필요할 때 서버가 선택한 후보 ID·목표·시각·revision을 함께 공유한다. 같은 Warp 정책으로 공유 유무만 바꿔 보정과 전송 비용을 비교한다. 지연 도착·중복·취소·교체를 포함한다.
- [ ] **소유 캐릭터는 별도 검증.** 소유 플레이어까지 범위가 넓어지면 saved move/replay와 교정 이벤트를 새로 검증한다. 시뮬레이션 역할에 따라 지표를 구분한다.

**완료 기준.** 역할별로 동일 사건을 추적할 수 있으며, 개선 효과와 추가 비용을 함께 보고한다. 기존 이벤트 기반 예측 결과는 연구의 동기와 측정 방법에 연결하고, Motion Warping 결과는 새 데이터로 검증한다. [Epic CMC 네트워크 이동](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-networked-movement-in-the-character-movement-component-for-unreal-engine)

## 10. 본 실험과 연구 산출물

- [ ] **조건 동결.** 빌드, 자산, 시작점, 충돌 프로필, 프레임 설정, 반복 수, 제외 기준을 평가 전에 고정한다. 프레임은 시계열 샘플이고, 비교 단위는 독립 Trial이나 대응 시나리오다.
- [ ] **분해 비교.** 기본 CMC → 안전 목표 → 환경별 후보 선택 → 필요 시 QP → 네트워크 계획 공유 순서로 한 요소씩 추가한 비교를 구성한다. 동일 자산 비교와 후보 선택 비교의 결과를 구분한다.
- [ ] **보고와 시연.** 평균·p95·최악값·실패율, 동작 품질과 전송·계산 비용을 함께 정리한다. 동일 카메라와 타이밍에서 벽 없음/가까운 벽, 성공/실패 사례를 시연한다.

**완료 기준.** 원본, 실행 조건, 집계 방법과 대표 영상을 연결할 수 있다. 각 개선이 어느 조건에서 효과를 냈는지, 단순 기준군으로 충분했던 조건은 어디인지 제시한다.

## 바로 맡길 첫 세 작업

1. **샘플 및 기존 자산 감사.** 01–02의 로컬 확인을 수행하고, 원본 Root Track을 검사할 후보와 부족한 자산을 목록으로 제출한다.

3. **최소 계측과 Pilot.** 04의 이벤트와 Capsule/Root/Mesh 기록을 연결하고 무장애·벽 접촉 조건의 원본을 확보한다.
