# M7. 손실·연속 사건·충돌에 대한 견고성

> 상태: 개발 예정. [전체 아키텍처](../Architecture/Unreal_Sharp_Movement_마일스톤_구현계획.md) · 선행: [M6](../M6/M6_시각_예측.md) · 다음: [M8](../M8/M8_최종_평가.md)

## 개발 및 검증 사항

**목표:** 예측이 틀어지거나 사건 전달이 누락되어도 결국 서버 상태로 복귀하게 한다.

**구현 작업**

1. `SequenceId`가 더 오래된 Snapshot은 무시한다. 같은 Snapshot을 두 번 적용하지 않는다.
2. RepNotify의 중간 사건 병합 가능성을 확인한다. 한 복제 주기에 연속 Impulse가 필요하면, `최신 상태만 있으면 충분한가`를 먼저 판단한다.
3. Unreliable RPC를 대안으로 시험할 경우 손실·순서 변경을 가정하고, Reliable RPC를 매 이동 틱 보내지 않는다. RPC와 프로퍼티는 실행 순서가 다를 수 있으므로 하나의 Snapshot과 SequenceId로 상태를 검증한다.
4. 벽 충돌, 착지, 정상 회전, 급정지, 여러 AI 동시 사건에서 예측 만료·수렴을 검사한다.
5. 지연·지터·패킷 손실은 Unreal Network Emulation의 `PktLag`, `PktJitter`, `PktLoss` 등으로 설정한다. `PktLag` 값 하나를 RTT 전체로 혼동하지 않는다.

**산출물:** 상황별 실패·복구 표와 보정 영상.

**완료 기준:** 사건을 놓쳐도 기본 이동 복제로 정상 상태에 복귀하며, 늦게 온 사건이 최신 위치를 다시 과거로 돌리지 않는다.
